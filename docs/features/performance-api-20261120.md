# 画布启动接口审计与优化（2026-11-20）

## 结论

画布可以使用启动专用接口，但只把已经并行的请求合并，不能解决数秒冷启动。实际有效的改动是：在账号绑定后立即读取启动数据，让数据请求与工作台代码加载重叠，而非等工作台挂载之后才请求。

本轮不迁移原生画布、不更换依赖、不改数据库结构。Android 原生代码与安装包没有修改。

## 调用链与实现

- 新增 `GET /api/project/:id/startup`，返回 `{ project, settings, assets }`。沿用 Cookie 鉴权、账号绑定、UUID 与工程归属校验；受限 Native Bearer 仍不能直接访问此接口。
- 服务端复用现有查询，并行读取工程、设置和资产目录。账号余额、模型、Skill、模板不加入画布首屏依赖。
- CloudSession 在账号绑定后启动预取，工作台后续读取设置、工程、资产时各消费一次同一响应。数据处理仍经过原有项目解析、导演台模型还原、引用核对与缺失文件恢复。
- 预取只用于首次直达画布，不使用长期业务数据缓存；三部分消费完成即释放响应引用，之后的刷新走现有接口。按项目及绑定账号隔离；其他项目与普通页面不复用。
- 旧服务器返回 404/405 时回退现有接口；503、权限失败等不伪装成空数据。失败后显式重试会发新请求。
- 启动响应包含 `Server-Timing` 的 project、settings、assets 查询耗时，供后续区分服务端阶段。该计时不包含此前的鉴权、网络传输和浏览器执行。

已有会话读取本就合并同时进行的请求，因此不能声称“以前三个请求必然查询三次会话”。新接口仍有三个服务端数据查询，本轮没有把它们压成单个数据库 RPC，也没有声称取得事务一致快照。

## 测量

隔离账号、空画布、真实部署数据库；没有调用付费模型。先对候选服务进行 10 组交替测试：三个旧接口并行读取与启动接口分别各 N=10，计时到 JSON 响应体完成。

| 方式 | P50 ms | 最小 ms | 最大 ms |
| --- | ---: | ---: | ---: |
| 原三个接口并行 | 616 | 419 | 1249 |
| 合并启动接口 | 601 | 417 | 776 |

这组结果只证明请求数量减少，差异很小，不支持稳定的接口提速结论。

随后使用本机 Chromium、独立全新浏览器 context、SSH 转发到同一服务器的旧生产容器与候选容器，交替测试，每宽度每版本 N=3。路由代理关闭 HTTP 缓存，资源来自远端真实构建；Agent connect 请求保持 pending，确认其不阻塞画布。计时到画布 DOM、启动层消失且主区域非 inert；没有 pageerror。

| 普通 Web 画布 | 原版本 P50 ms | 最终候选 P50 ms |
| --- | ---: | ---: |
| 390 宽 | 4649 | 3692 |
| 1280 宽 | 4178 | 3595 |

工程启动阶段的标记进一步支持重叠已经发生：例如 1280 宽候选的一次样本，从 preferences-start 到 project-ready 仅约 5 ms；启动数据的真实请求仍耗时约 758 ms，已在此前完成大部分等待。原版本对应阶段仍有约 800 ms 等待。整个页面仍有脚本下载、执行和登录检查成本。

嵌入式 Web 桥接模拟 N=3：原版本 3644 ms，候选 3682 ms，未显示稳定端到端提速。其代码路径不受最后撤回的普通 Web 提前下载实验影响。它不是 Android 模拟器或真机验收，不能据此更新 Android 0.9.15 首次画布 7550 ms 的历史成绩。

另做过普通 Web 提前下载整个工作台的实验，部分登录请求变慢，页面收益不稳定，已撤回。最终版本保留既有原生工作台预热，只新增启动数据预取。

这些都是小样本、测试网络与空工程数据，不发布固定提升百分比，不保证真实手机达到上述时间。

## 其他接口方案的判断

| 方案 | 判断 |
| --- | --- |
| 合并设置、工程、资产启动请求 | 已实现；配合更早请求才有实际首屏收益 |
| 合并账号、余额、模型、Skill 到启动接口 | 不纳入画布首屏；会重新引入慢上游依赖 |
| 资产目录只返回当前工程引用 | 暂不实施；现有引用核对会写回目录，直接返回局部数据可能覆盖其他记录，需先改为增量写接口 |
| 多媒体签名、存在性批量接口 | 可减少含大量生成素材的工程请求；本轮空工程不能验证收益，尚未实现 |
| 项目库列表与文件夹合并 | 可减少外围请求，但不是本轮画布首屏的主要依赖，尚未实施 |
| 服务端把三份数据合为单个数据库 RPC | 仍可评估；当前已并行，需用数据库阶段计时证明收益，再增加迁移 |
