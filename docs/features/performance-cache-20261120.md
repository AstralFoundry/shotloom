# App 画布资源预加载修复（2026-11-20）

## 问题与实现

App 原来已有后台资源预下载：原生 WorkspaceSession 在登录后通过一次性票据打开轻量页面，下载工作台入口、ReactWorkbench、AntdProvider 及静态依赖，不执行工作台、不读取项目数据。此前“没有预下载流程”的描述不准确。

实际线上问题是构建清单没有与页面同步发布。检查时生产版本为 20261120-polyfork-001，页面入口 main-DGdEn4AT.js，而镜像中的 .vite/manifest.json 入口仍为 main--W8CZWKm.js。旧哈希资源保留使预下载仍能成功，但许多当前画布文件没有预先缓存。

- 将已有的静态依赖收集函数移到 shared/workspacePreloads.ts，由构建与服务端共同使用。
- Vite 构建完成写出文件后，将预加载列表作为不可执行的 JSON 元数据写进 index.html。它随同页面发布，不再依赖额外同步的清单文件。
- 服务端优先读取页面内的列表，验证路径限定在本域 assets 下的 JS/CSS，并确认列表包含该页面的入口。
- 没有内嵌列表的旧构建仅在清单与页面入口一致时使用清单；不匹配或不可读时记录警告并跳过预热，实际画布仍正常加载。
- 保留原有 HttpOnly Cookie 交接、账号绑定、接口权限、下载失败回执和缓存策略。未缓存用户业务数据，未扩大 Native Bearer 权限。

没有修改 App 原生代码，不需要新的 APK。未改跨项目 WebView 重建或未保存状态的生命周期。

## 公网验证

390×844 桌面 Chromium，每组 N=3；每个样本独立新浏览器上下文，冷/预热交替执行。通过真实服务端票据获取预热 HTML，同源执行预下载；关闭该页面后，在同一上下文的新页面打开画布，模拟共享资源缓存的新 WebView。没有使用请求路由拦截，没有禁用 HTTP 缓存，也没有人工延迟 Agent。

预热后样本等待下载完成，计时从打开实际画布文档到 viewport 出现且启动遮罩消失。不是完整 App 启动时间，也不是 Android 真机结果。

| 项目 | 修复前 | 发布后 |
| --- | --- | --- |
| 未预热画布耗时 ms | 4896 / 3826 / 4328 | 4078 / 2751 / 3637 |
| 预热后画布耗时 ms | 1333 / 1284 / 1746 | 1077 / 1733 / 1060 |
| 预热后耗时中位数 ms | 1333 | 1077 |
| 预热后实际画布静态 JS/CSS 传输字节 | 1079629 / 1079629 / 1080639 | 1010 / 0 / 0 |
| 预热后已缓存的主要 JS/CSS 文件 | 5 | 13 |

发布后的 1010 字节来自额外动态加载的 modelPublications 模块；预加载清单中的 13 个主要文件均命中缓存。发布后静态下载阶段耗时 1625 / 2249 / 1206 ms，不包括此前的票据和登录交接成本。预加载把下载前移，并没有让这部分成本消失。

冷启动代码哈希保持不变，只有页面元数据和服务端读取逻辑改变；冷样本耗时波动不能解释为冷启动执行性能提升。小样本、非同时对照，不承诺固定加速比例。尚未预热完成、首次联网、缓存被系统清理时仍需下载资源。

原始证据位于主工作区 output/canvas-cache-20261120/baseline.json 和 released.json；脚本 probe.mjs 记录资源传输大小、缓存事件及页面错误。全部样本无 pageerror。
