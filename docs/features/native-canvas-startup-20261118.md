客户端继续使用 0.9.8 / versionCode 9，签名构建 `44113767890`。本轮没有修改或重打 APK；已打开的 WebView 文档需要重启 App 才能加载新版入口。

## 改动与依赖

仅调整带有 `native=embedded&project=...` 的云端启动路径：

- 设置、技能、模板并行读取。
- 删除启动时预读的素材库和项目目录；打开项目时本来就会读取最新素材目录、校验引用并刷新项目列表。
- 指定项目不存在或无法恢复时，仍读取项目列表供用户返回。
- 普通网页版和桌面启动保留原有初始化流程。

登录校验、权限、项目读取和素材引用校验仍是前置条件。本轮没有增加 KV、TTL 或用户数据缓存，没有修改 Supabase 表结构。

## 浏览器网络采样

使用相同隔离测试账号、空项目、390×844 视口，每轮清空 HTTP 缓存。时钟从导航至 WebView `workspace-ready`；不包含原生一次性交接票据的耗时。

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 三轮就绪前 API 请求数 | 16、16、16 | 12、12、12 |
| 三轮冷加载耗时（ms） | 25267、15992、12097 | 43045、15502、10444 |

请求数稳定减少 4 次（25%），分别为一遍素材目录和一遍最近项目/文件夹/项目列表。耗时波动较大，改动后第一轮直到约第 32 秒才完成工作台脚本下载，因此这组浏览器数据不能证明稳定的端到端提速比例。脚本体积没有减少。

没有伪造成功模型响应；测试账号缺少真实上游网关授权，账户/模型错误仍真实返回，画布可以继续打开。没有进行付费生成。

## Android 验收

相同已签名 APK、相同页面测试脚本，公网服务器使用本轮 Web 更新。运行 `44132325551` 的 attempt 2 完整通过，包含 168 个页面样本和 195 个接口样本，三轮页面 failure 均为 null。

| 画布指标（ms） | 上轮 0.9.8 | 本轮 |
| --- | --- | --- |
| 三次首次打开 | 18581、13439、19801 | 19104、15688、14139 |
| 首次打开中位数 | 18581 | 15688 |
| 再次打开中位数（各 12 次） | 2379 | 3479 |

本轮首开中位数约减少 2.9 秒，但再次打开没有改善，反而增加约 1.1 秒。不能据此宣称所有画布切换都提速，后续仍需要对保留 WebView 的显示、布局和可访问性读取分别采样。此次产品修改只发生在文档初始化，APK 和保留 WebView 的切换逻辑没有变化；尚未证明再次打开变慢由本轮代码引起。

两轮测试并非同时 A/B。Android 直接 API 采样中 `/auth/me` 中位数为 814→698 ms、`/projects` 为 748→716 ms，网络条件有所不同，不能把首次打开的全部差值归因于代码。

attempt 1 的前两轮已有 112 个页面和 130 个接口样本，页面均成功，第三轮发生 ADB device offline / emulator connection refused，没有生成第三份有效结果；保留其证据，不混入最终三轮中位数。成功重跑的 artifact 创建时间为 2026-11-17 UTC / 2026-11-18 上海时间。

测试结束后，已删除隔离测试用户及会话，确认原生凭据失效为 401；三个临时 GitHub 验收 secret 已移除。
