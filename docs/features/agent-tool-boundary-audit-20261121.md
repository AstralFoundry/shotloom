## 已确认并修复

1. **导演会话 ID 被 Harness ID 遮盖。** 产品结果外还有传输与产品记账两层包装。模型输出只展开一层，会把聊天 ID 当成导演运行 ID。共享渲染器现只移除已识别的包装，保留真实 sessionId、revision、失败码、引用与图片。真实会话变化仍返回 SESSION_MISMATCH，不能改 ID 后重放旧批次。
2. **生成权限关闭误报断连。** canvas_start_generation 的 isAvailable 在权限分支前抛错。现返回 NODE_EXECUTION_DISABLED；全权限也不能覆盖生成开关。
3. **其他不可用工具与参数错误也误报断连。** 关闭文本/剪辑编辑器、运行端不支持某后端、调用其他角色工具，原先都会抛到 Host 的 BRIDGE_UNAVAILABLE。共享产品边界现分别返回 TOOL_UNAVAILABLE、TOOL_NOT_ALLOWED、INVALID_TOOL_INPUT，并保留 applied:false、修复提示和参数问题；未知绑定和工程身份校验仍严格执行。
4. **工具自己的超时声明丢失。** 产品目录没有传递 timeoutMs，Host 固定用 120 秒。10 个声明不额外限时的工具（8 个 OpenReel 渲染/导出、video_project_export、director_editing_handoff）以及两个 130 秒导演查询/命令都受到影响。目录与 Host 现保留工具声明；授权预检仍使用桥接默认期限，执行中的 0 表示不额外添加超时，用户取消始终有效。
5. **Worker 取消未到达工具上下文。** 原先只停止等待回执，context.signal 是永不取消的独立信号。现由 Worker host-abort 经过页面处理器、集成层传到每次产品调用，已有手交接等异步检查点可以停止后续步骤；抽帧循环也检查取消。已经执行的操作不会自动回滚；未实现取消的原生渲染本身也不会因此获得中断能力。
6. **24 张逐帧图超出 Harness 的 8 张限制。** canvas_media_frame 在 frames/default 模式允许提取 24 帧，附件保存阶段必然 TOO_MANY_IMAGES，最后被误报为 BRIDGE_UNAVAILABLE。现提取前返回 IMAGE_ATTACHMENT_LIMIT 并提示拼图或分批；contact_sheet 仍允许 24 个时间点并只交付一张图片。

前 1、2、3、4、6 项属于共享产品/Host 合同问题，不能全部归因于本地 Worker。第 5 项是 Worker 到页面工具执行之间漏传取消信号。

## 保留的正确边界

- 不可用工具不执行；编辑器、工程和绑定变化后不能改到其他目标。
- 付费生成、删除、覆盖、导出与用户审批继续生效；不根据自然语言猜意图。
- 不确定的写入返回 TOOL_OUTCOME_UNKNOWN，读取实际状态后由 Agent 决定下一步；不自动重试付费或写入。
- 工具动态副作用只能从静态最大权限向只读降级，不把潜在写操作并发执行。
- 真实附件字节、图片校验、官方持久化和会话恢复继续沿用已有实现。

## 验证与限制

新增回归先复现超时目录丢失、关闭编辑器抛异常、取消后仍写入和 9 张图片无前置拒绝，再验证修复。Host 回归直接执行官方工具服务，验证 0 / 自定义 / 默认超时；页面传输回归验证 host-abort 到达产品处理器。原有绑定、角色隔离、审批、去重、媒体、导演运行会话与真实浏览器 Worker 回归一并执行。

未逐个运行付费媒体生成、全部原生编码器、GPU/3D 渲染或真实设备安装包。真实断网、上游模型断流和浏览器关闭仍可能中断任务；这些修复不承诺自动恢复所有外部操作。部署断流、登录心跳与发布排空流程另见 agent-network-recovery-20261121.md。
