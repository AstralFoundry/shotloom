## 修复的实际竞争问题

1. 页面导航取消旧请求时，服务端共享鉴权读取曾继承旧页面的 AbortSignal，造成下一页鉴权和启动 500。修复把共享读取从单个调用者取消中分离，同时保留原始 15 秒截止时间。回归覆盖嵌套共享读取不能续期；真实浏览器失败记录保留在单独目录。
2. 完整目录编辑者 A 的快照过期后，曾可借用新读取 B 的 revision 保存差量并误删 B 新建条目。完整读取现在携带 `__catalogRevision`，保存比较原快照；旧版本返回 409，扩展元数据经过 store 克隆/保存仍保留。
3. 素材存在性不确定时，403、超时、网络错误不能伪装成缺失；只有明确缺失才恢复远程生成结果。失败项保留持久路径，恢复期间不保存未完成工程。
4. 剪辑器解码过程中更改名称/元数据，延迟恢复不能用旧快照覆盖后续编辑；恢复仅替换对应媒体字节，保留当前属性。
5. 首轮完整对照发现冷启动和媒体首帧回退。进一步修复语言读取导致的整页重载、已签名素材重复签名及屏幕外预览抢占。修复前数据归档，不与最终候选样本混合。
6. 请求结束后的后台回调继承旧计时上下文，可能用过期预算发起共享鉴权读取，进而影响并发页面请求。HTTP 响应结束后不再向独立后台任务传播旧信号；已在途共享读取继续保留自己的原始预算。嵌套共享读取仍不能续期。真实工作区联调曾复现该错误，修复后重新执行。
7. 初始页面 ready 前 UI 路由仍为默认项目库，会让 Skill 等页面短暂请求无关项目数据。现在 ready 前同步请求的路由。已知语言的热启动继续并行读取设置与工作台模块；缺少语言时才提前准备偏好，避免冷启动整页重载。
8. Skill A 已打开、B 详情读取中，再选择 A，曾无法使 B 的迟到响应失效。已加入失败回归并修复选择序号。

9. 多个读取入口并发请求同一图片时，预览和源文件曾重复下载。真实失败样本中 1.6 MB 图片下载持续 152–169 秒；Nginx 同期记录 145–158 秒，不能归因成纯 SQL 或 DOM 问题。`cd8c582` 在云读取层合并同身份/源路径的在途字节读取，失败释放后允许重试；新增回归先失败后通过。该次部分采样单独保留，不混入最终数据。

10. 偏好预取超时后，失败 Promise 被已挂载工作台继续复用，导致列表已恢复却仍显示初始化错误，且没有切回账号语言。`8988898` 丢弃失败的偏好/画布启动预取，后续正式读取保持独立；30 项相关测试通过，并用真实浏览器注入首个偏好请求超时，确认页面恢复英文、20 个项目条目可用。该失败采样归档。

## 接口兼容与数据边界

| 接口 | 新客户端行为 | 旧行为 / 回退 |
| --- | --- | --- |
| `GET /projects/page` | folder / search / sort / offset / limit；items / total / offset / limit | `/projects` 保留；仅新端点明确 404/405 时读旧接口 |
| `GET /project/:id/summary`、`PATCH /project/:id` | 重命名只读摘要并携带 expectedRevision；409 刷新后重试 | 旧完整工程读取/保存保留，名称更新不重写节点和任务 |
| `GET /catalog/:kind/page`、`GET /catalog/:kind/item/:id` | 摘要用于列表；完整详情用于编辑 | 完整目录仍供旧客户端和 Agent 使用；权限/503 不回退为空 |
| `PATCH /catalog/:kind` | expectedRevision、upsert/remove、metadata；冲突 409 | 仅端点不支持时回到旧完整读取/保存；摘要不能提交到完整保存 |
| `PATCH /settings/preferences` | 仅偏好写入，返回规范化偏好；不等待额度和模型 | 旧设置接口保留；Native 使用 `/settings/mobile` |
| `POST /files/check`、`POST /files/sign-batch` | 每批最多 200；逐项 exists / missing / error；逐对象归属和路径校验 | 仅新端点 404/405 才逐项旧读；403/超时不当成缺失 |
| `GET /notifications/unread` | 通知面板关闭时只取数量 | 原列表、详情、已读和 asOf 保留 |
| `GET /project/:id/startup?parts=project,settings` | 只请求画布必要启动数据 | 老启动及单项接口兼容 |

写请求不会自动重放。权限检查、执行授权、扣费和支付不使用展示缓存。服务端每次业务请求仍验证会话及账号；列表及对象访问继续校验归属。观测日志没有 Token、Cookie、签名 URL 查询字符串或业务正文。

服务端展示缓存：模型 30 秒、发布配置 60 秒、账号/用量 5 秒、充值比例 300 秒、单项媒体签名最多 120 秒且早于过期；最大 256 项，仅成功结果缓存。Renderer 可选摘要缓存 5 秒、64 项；签名缓存 120 秒、500 项，账号绑定时清空。Native 原有进程内展示缓存为 60 秒，手动刷新/写入失效；不用于权限判断。

## 测量方法

- 固定隔离账号、45 工程、65 个含正文 Skill、48 个 1920×1080 / 1,612,729 字节 PNG、一个带云模型引用的导演工程。
- 正式 Web 使用同一次 Ubuntu 24.04 CI 作业中的同一 Chrome 进程，浏览器版本随证据记录；390×844 / 1280×844，项目/Skill/账号/设置/空画布/多素材画布。冷、缓存热启动及前三页进程内返回；每组至少 10 次，交替版本顺序。
- 扩展采样单独记录资产库、素材、任务、充值展示、反馈历史、通知、管理后台四区、导演和剪辑器。资产/素材通过实际搜索和菜单进入，任务通过画布侧栏进入，避免旧版深链接路由竞争；后台各区从对应标签进入；充值仅展示，不创建订单。扩展数据不混入原 600 个核心样本。
- 本机 Windows 公网的早期/失败记录单独保留，包含 150 秒媒体传输和 15 秒偏好超时。正式 CI 换了网络和硬件环境，因此两组不能混合计算；CI 对照不代表国内用户或物理手机的公网收益。

## 验收限制

- 生产 Web/BFF 按用户追加授权发布；未执行付费生成、真实充值、iOS 真机或 Android 物理手机验收。
- 隔离网关和小型数据库只验证请求链路及对照条件，不能承诺真实公网固定提速比例。
- 生产版本没有可靠 revision 标签，重建基线存在已记录的 Native allowlist 差异；不能声称所有现网 APK 已与本基线完全一致。
- 工作台仍下载两个语言 chunk；Native 展示缓存仍沿用原有 60 秒策略。项目内素材页面仍复用完整工程事实，没有切成工程级分页 API；全局材料投影接口已提供。这些是本轮未完全达到原细项的部分。
- 完整交付状态以最终配对结果、功能联调、清理与残余问题记录为准；不隐藏回退或未通过的检查。
- 首轮正式 Web 采样期间，Nginx 共记录 20 次 `POST /api/agent/:id/bind` 返回 500。这条绑定/持久化链路与基线代码一致；只读诊断发现 8 个 Agent 会话对应 7 条持久化绑定。两套 BFF 共用同一隔离账号，旧实现整份保存绑定列表，存在快照覆盖的可能；目前没有异常消息证明具体原因，不能宣称已修复，也不能把 500 算成正常导航取消。页面计时与该残余问题分开披露。
