# 界面多语言

- 中文文案：`locales/zh-CN.json`；英文文案：`locales/en-US.json`。
- 界面通过 `t(key)` 读取文案；动态值使用完整句子的占位参数，如 `t('project.exported', { count })`，不拼接有语序关系的词语。
- 新增或修改词条时同步两份 JSON，键保持稳定，不将中文原文作为键。
- 修改含参数词条后运行 `node scripts/generate-i18n-types.mjs`，再运行 `npm run check:i18n` 和 `node --test tests/i18n.test.mjs`。
- 语言在“设置 → 通用 → 界面语言”中切换。切换前保存当前工程，刷新后统一应用模块级标签和独立 iframe 的语言。
- 厂商模型目录的 `labelKey`、`optionLabelKeys` 只控制展示。新增目录标签需同步 JSON 译文，提交协议与参数值不翻译。
- 官方 Harness 文案通过官方 locale 服务处理；Shotloom 的自有界面复用本目录字典。聊天 iframe 的译文和文档 `lang` 统一由 URL hash 的 `shotloomLocale` 决定，不读取 iframe 自身的语言缓存；未知或缺失参数回退中文。聊天嵌入客户端的启动失败和缺失组件提示也使用该字典，插件 ID、目录阶段和上游错误作为参数保留。三维导演台只导入纯文案函数，不导入产品状态。
- OpenReel 产品桥接的导入、恢复、重关联、导出提示与默认名称同样复用 JSON 字典；独立运行时按宿主语言配置翻译，局部文档同步 lang/title。共享字典纳入嵌入产物的构建哈希。上游英文界面和中文覆盖层保持各自的语言入口。
- 剪辑运行时验证：在 `vendor/openreel/apps/web` 运行 `npx vitest run src/shotloom-mode.test.ts src/shotloom-bridge.recovery.test.ts src/shotloom-i18n.test.ts src/embedded/dom.test.ts`，覆盖语言隔离、导入/字幕导出错误和原始文件名/错误详情保留。
- 剪辑字幕数量、搜索范围、分页、字幕选择和批量文字提示直接复用产品 JSON 的完整句子，参数类型同样由根脚本生成。`editorMessage` 在独立上游界面默认英文，嵌入工厂挂载前按宿主语言配置；不从剪辑组件读取产品 Store。
- OpenReel 属性面板新增的固定说明集中于 `vendor/openreel/apps/web/src/shotloom-i18n-inspector.json`（235 条）。这是现有上游英文覆盖层的精确匹配词典，英文仍使用上游界面，产品自有文案继续使用稳定语义 key。
- OpenReel 中文覆盖层包含属性面板锚点、文字动画和轨道显隐等无障碍标签。动态模板只对明确的固定面板标题（`section`）与媒体类型（`type`）查译文，片段/轨道/文件名等用户参数原样回填；面板展开/收起两种状态均翻译；时间线的真实文字和已命名轨道使用 `data-shotloom-user-content` 标记，缺省界面标签仍可翻译。
- 导出校验/浏览器编码探测返回结构化 `ExportPreflightIssue`（错误类型及原始参数，含缺失素材、In/Out 范围、重复导出与音频预检），界面通过 `exportPreflightMessage` 读取 JSON；底层错误继续保留英文兼容信息，`ExportError.preflightIssue` 将结构化信息传到导出执行器。界面不按错误原文匹配译文，探测失败的上游详情按一次占位符替换保留；没有结构化信息的第三方错误仍原样显示。
- 导出执行器的文件位置、空文件、内存下载上限、写入数据/命令、重复导出错误，以及初始化/保存完成状态和系统文件类型名称直接通过 JSON 读取。音频导出与视频导出共用结构化错误翻译，取消仍通过 AbortError 处理，不改变取消语义。
- 压缩弹窗与导出设置的画质档位、保存方式、浏览器限制、硬件状态、动态大小/码率/进度说明直接复用产品 JSON；压缩与导出参数继续使用原始枚举，文件名和设备型号原样显示。组件测试使用受控媒体探测/编码器，验证中文操作与英文操作提交相同参数，并保留下载文件名；不将模拟编码测试视为真实视频编码实测。
- 尺寸匹配弹窗、导出阶段、快捷键说明、关键帧选择、模板名称长度，以及节拍同步/滤镜/动画预设统计和效果搜索空结果使用完整 JSON 词条；搜索词、轨道名称和上游错误作为参数保留，动画类别只翻译展示值，不改变原始枚举。
- 代理预览、效果处理和运动跟踪的数量/进度提示使用完整产品词条。代理预设与任务状态仍使用原始枚举值，展示名称在组件里翻译；背景移除的固定进度与通知在产生位置翻译，用户媒体名及上游错误/任务详情保持原文。
- 工具卡片的数量摘要使用 `formatToolCount`，词条包含完整数量短语和英文单复数；空结果保持空摘要或明确的无结果提示。工具失败提示只翻译产品拥有的固定文本，原始文件名、任务 ID 和上游错误参数保持原值。
- 日期展示使用 `getLocale()`；数量短语使用带参数的完整词条，英文单复数分别登记（如 `formatItemCount`），不要把数字与 `items` 碎片拼接。
- 技能分配角色名与厂商图标目录的中文名称通过字典展示；Agent ID、工具白名单、Skill 归属和图标资源不依赖翻译。
- 系统音色名称和语言标签可翻译，音色 ID、语音语言值和默认音色保持原值。
- 新建三维对象的默认名称按当前语言生成；读取既有工程时保留已保存名称。任务状态 ID 与颜色语义不随翻译改变。
- Rust 原生错误可用 `localized_error.rs` 的 `localized_error`（命令层通过 `commands/common.rs` 重导出） 返回 `shotloom:localized-error` 信封（key、params、fallback）；前端只翻译显式信封，参数缺失或键未知时使用 fallback，其他上游错误保持原样。
- SQLite 边界只对结构完整的翻译信封保留原始 JSON；其他 ORM 错误按原有格式返回，避免把数据库详情误认为文案。
- Shotloom 工具的 `title` 和面向用户的 `summarizeInput`/`summarizeResult` 也是界面文案，应使用字典；`description`、schema、工具 ID、权限与模型使用的协议内容保持原样。OpenReel 的已支持工具标题按 `tool.openreel.<name>` 登记到两份 JSON，英文使用上游标题；未知工具回退上游标题。升级目录后补齐对应词条，双语测试会检查整个支持目录的覆盖和 schema 一致性。
- 内置 Skill 的用途说明与分类标签在列表展示和搜索时翻译，使用 `skillDisplayDescription` / `skillDisplayCategory`；只有字段仍与随包基线相同时才应用译文，用户修改与自建内容原样保留。编辑表单、Agent 正文和导出数据使用原始字段。
