# 逐镜状态与跨镜接力

在故事板确定后、编写逐镜视频提示词前读取本文件。状态写进现有 Production Plan 的镜头工作项，并用真实 `shot_id`、节点 ID 和参考资产关联；不另建一套项目文件或状态引擎。

对需要承接的镜头，分别写清进入与离开时可见的事实：场景固定地标、人物位置和朝向、视线对象、入出画边、行进方向、哪只手持有什么道具、道具放置或交接后的状态、机位位于动作轴线哪侧，以及有依据的主光方向。用门、台阶、桌案等场景地标先固定物理位置，再写画面左右；反打可能改变屏幕左右，不能据此改写人物的真实站位。没有来源证据的位置和动作不要编成精确米制坐标。

相邻镜头按剧情关系核对：同场连续动作要解释前镜离开状态如何到达后镜进入状态；切机位时保持人物、道具、光源与运动方向可理解；换场、跳时或剧情明确重置时记录重置依据。某角色离画后仍保留离画边、持物和运动方向，直到重新入画或场景重置。发现冲突时先修正受影响的分镜、参考图或提示词，不让一个矛盾参考继续进入视频节点。

上一镜尾帧只是可选的连续性锚：只有同场景、机位与轴线关系相容、前镜视频已有真实成功输出，且当前视频模型支持该输入时才考虑使用。使用前核对尾帧确实表现前镜的结束状态，并继续连接当前镜头需要的人物身份、场景与分镜参考；不能把一张尾帧当成全部身份和空间依据。切场、反打、越轴、身份或道具状态改变时，优先使用当前镜头自己的参考输入，不强行串尾帧。前镜重新生成后，旧尾帧不能继续冒充当前选用结果。

只有共享同一前镜成功输出的后续镜头需要等待这条尾帧依赖；其他无依赖镜头可以按真实输入就绪状态继续。画布里仅表达模型真正消费的输入边，镜头先后顺序保存在工作项和剪辑执行单，不用无语义连线假装生成依赖。
