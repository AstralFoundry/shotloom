# 剧本生视频（需上传剧本）

这个 Skill 只处理已经存在的剧本，不把一句创意、故事梗概或小说章节假装成完整剧本。首先检查本轮附件、用户明确引用的画布文本节点和素材库事实；若没有可读取的剧本正文，调用 `request_clarification` 请用户上传 PDF、图片或文本剧本，或指定已有文本节点。不要因为内部字段缺失重复询问已经明确的信息。

读取剧本后先用一句话忠实概括故事，不改写台词、动作结果、场景顺序和结局。图片或扫描 PDF 中无法可靠识别的内容应指出具体缺页或模糊位置，不得补写。用户已提供的角色、场景、道具、音色、图片、视频和音频必须优先复用：先用 `canvas_list_nodes` 核验真实资产，需要放回画布时通过 `canvas_create_node` 的 `place_asset_on_canvas` 类型创建真实素材节点，再用 `canvas_connect_nodes` 建立真实输入边；已上传且可直接绑定的元素不编写生成 Prompt Draft，也不重新生成。

这是多阶段协作制作，使用 Production Plan 保存阶段、工作项和真实 `runtimeRefs`。每次只推进到下一个审阅点；用户确认当前产物后再继续，不在一轮中跨过多个确认点。确认是对成片规格、故事板或具体 Prompt Draft 的内容审阅，不替代“允许 Agent 运行节点”的权限设置，也不能绕过真实生成权限。

## 画布执行协议

- 进入一个阶段时先用 `canvas_list_nodes` 的 `timeline` 或 `summary` 掌握相关节点；已知剧本、规格、故事板、元素或镜头节点后改用 `canvas_get_node` 局部读取。只有需要从素材库取回资产时才使用 `full`。
- 每个 Note 或生成节点分别通过 `canvas_create_node` 创建；后续直接使用成功回执里的真实 `nodeIds`。配置修订使用 `canvas_update_node`，输入依赖使用 `canvas_connect_nodes`，并显式填写当前模型契约要求的 `role`、`slot` 和节点 `inputMode`。
- 先由本 Skill 根据剧本确定阶段、`element_id`、`shot_id`、依赖和故事顺序，再调用 `canvas_layout_nodes` 整理明确的节点集合。布局工具不会从标题、节点类型或文案猜测故事结构，不能用无输入语义的连线表达先后顺序。
- `plan_canvas` 到真实节点与输入边就停止。`plan_and_execute` 只用 `canvas_start_generation` 启动当前依赖已经满足的节点，保存每次 task 回执，再用 `inspect_tasks` 核验终态；不得把已提交、运行中或布局完成当成媒体完成。
- 任一写入发生 revision 冲突时重新读取相关节点，只修复尚未成功的动作；已经返回成功 `nodeIds`、`edgeIds` 或 `taskIds` 的操作不得整批重放。

## 原生阶段

### 1. 剧本准备与成片规格

把剧本来源放到画布或引用已有真实节点，并建立一句话故事总结。创建名为 `Final_Video_Spec.md` 的 Note，至少写明：标题、内容类型、目标观众、画幅、预计总时长、单镜最大时长、视觉风格、主色、输出语言、对白语言、是否需要旁白、音乐方向、目标清晰度和模型偏好。任何会显著改变镜头数量、节奏或交付成本的缺失规格，由 Router 一次性集中询问。

规格草案完成后在回复中给出可审阅摘要并暂停；用户确认或修改后才能设计故事板。

### 2. 忠实故事板

故事板必须以剧本和已确认的 `Final_Video_Spec.md` 为唯一事实依据。可做的技术编辑只有：把一次模型无法完成的内容拆成不超过 15 秒的连续镜头，以及补充专业镜头语言。不得增删剧情、改写逐字台词、改变动作结果或调换场景顺序。

先建立稳定元素清单：角色、关键生物、场景、关键道具和音色分别拥有唯一 `element_id`。角色描述记录脸型、五官、体型、发型、服装与剧情允许的状态变化，并记录声音、语速和音色；场景描述记录空间结构、重要物体的位置与朝向、表演区域和光向；道具描述记录外观、材质、尺寸、状态及持有关系。用户指定的参考资产必须与真实可见内容一致。

逐镜使用唯一 `shot_id`，每镜写明：所用场景和元素 ID、剧情动作、逐字台词或旁白归属、景别、角度、摄影机运动、起始状态、结束接点、目标时长和音频层。默认一次视频节点对应一个连续长镜头；真实切镜、换场或不连续时间拆为不同 `shot_id`。只有当前 Seedance 模式明确支持多镜叙事时，才允许在单镜描述内使用“镜头1、镜头2、镜头3”排列内部剪切，不用精确秒点强迫模型执行。

声音层至少说明全局音乐方向；剧本存在对白或旁白时，分别记录逐字内容、说话者、声音/语气和覆盖镜头。故事板以 Note 节点保存并通过 `runtimeRefs` 绑定计划工作项，完成后回复用户审阅并暂停。

### 3. 元素图 Prompt Draft 与强制确认

在创建或启动任何缺失元素图的生成节点之前，先为每个待生成元素编写完整 Prompt Draft。中文界面或中文输入时使用中文提示词；对白仍遵守 `Final_Video_Spec.md` 的输出语言。每份草案必须包含：资产类型、`element_id`、完整 prompt、推荐模型、模式、画幅、分辨率、真实参考输入及每项输入的约束职责。

图片 prompt 只描述物理可见内容，用自然语言融合专业视觉风格、景别和构图、主光与负补光、克制调色、材质细节以及可见的姿态或微表情。不要解释角色动机，不要模仿在世艺术家的独特风格。除非剧情明确需要，避免红蓝霓虹对撞；优先让单一主色覆盖约九成画面。需要准确画面文字时用引号包裹 exact text；关键元素资产本身不生成文字。

角色优先采用横向 16:9 开发总板：半身主像加正面、侧面、背面完整全身视图，所有区域严格保持身份和服装一致。场景和道具只建立下游确实使用的视觉依据，不为了凑数量生成。

将整批元素 Prompt Draft 保存为 Note，并在回复中展示完整草案；随后调用 `request_clarification` 邀请用户确认或指出修改。用户提出修改时更新草案并再次确认。没有明确确认，严禁创建、配置或启动对应的图片生成节点。

### 4. 元素资产生成

确认后，对用户未提供的元素创建图片生成节点，使用 `script-element-reference` Recipe。读取单次模型能力快照：优先选择已配置且可用的 Nano Banana 2，即目录中的 `gemini-3.1-flash-image`；只有所选模式真实提供清晰度参数时才请求 2K，否则使用目录声明的实际规格并在 Prompt Draft 中如实标注。如果该模型不可用，选择支持所需参考输入和规格的兼容图片模型，并向用户披露替代。模型与模式不得仅凭名称猜测能力，也不能把不受支持的参数写进 config。

`plan_canvas` 只建立已确认的真实节点、prompt、model、`recipeId`、`outputSpec` 和输入边，不启动任务。`plan_and_execute` 在用户已开启节点运行权限时启动当前无依赖阻塞的元素节点，并使用 `inspect_tasks` 等待真实完成。全部元素完成后核验身份、服装、材质、场景结构和道具状态；失败项只修复回执指出的问题。向用户展示本阶段结果并暂停。

### 5. 镜头视频 Prompt Draft 与强制确认

元素图取得真实成功输出后，逐镜编写视频 Prompt Draft。每份包含：`shot_id`、使用的元素资产、每项参考输入职责、完整 prompt、推荐模型和模式、画幅、时长、分辨率及音频要求。低风险且主关键帧已经真实融合全部约束时可以只用该关键帧；身份特写、多角色、非人主体、关键道具、严格空间或复杂动作仍需按模型能力连接必要的角色板、场景板、道具板或动作板，不固定参考数量，也不堆入无关输入。

Seedance 2.0 prompt 按“摄像机 → 主体 → 空间 → 音频”顺序书写：先写机位、景别、焦段和运镜，再按先后写具体身体部位动作、表情与视线，然后写人物与背景的空间变化，最后写声音。动作需说明幅度、速度、方向、接触、停顿和因果。口头对白使用 `{逐字台词}`；非默认语言先标注语言；音效使用 `<声音描述>`；模型内音乐使用 `(音乐描述)`；必须生成的屏幕标题使用 `【精确文字】`。独立旁白不写入视频 prompt。默认结尾加入 `no music` 和 `no subtitles`，并追加与本镜相关的身份漂移、肢体、口型、服装、道具、空间、闪烁、跳帧、果冻感、错误文字和风格漂移负面约束。

不要用“0–3 秒、3–6 秒”编写精确逐秒命令。需要多节拍时按自然发生顺序描述；需要真实切镜则拆成多个节点。将整批镜头 Prompt Draft 保存为 Note，在回复中展示完整草案并调用 `request_clarification` 暂停。没有明确确认，严禁创建、配置或启动对应视频节点。

### 6. 剧情镜头生成

确认后创建视频生成节点，优先使用已配置可用的 `doubao-seedance-2-0-260128`、`script-seedance-shot` Recipe 和 720p 输出，每个节点 3–15 秒。若标准模型不可用，可在能力快照确认后选择 Seedance Fast、Mini 或其他兼容模型；若替代会失去参考图、对白、音频或分辨率能力，必须先披露交付降级。

每个视频节点连接当前镜头真实需要的元素图片或音色资产，prompt 明确映射输入职责。等待所有任务真实完成，逐镜核验剧情、身份、台词、动作、空间和首尾接点；不能用已提交或运行中冒充完成。向用户展示镜头结果并暂停。

图片输入的视频内部适配由运行时自动完成，不规划或创建额外的内部预处理节点。

### 7. 声音与剪辑交接

依据故事板生成对白、旁白、音乐和拟音。存在兼容音频模型时使用 `video-audio-design`；不存在时创建 `video-audio-production-sheet` 文本节点，明确它是声音后期执行单而不是已生成音频。用户已上传音色参考时，将真实音频输入绑定到相应角色，不能用文字说明冒充连接。声音节点或执行单就绪后向用户展示结果并暂停，确认后再进入剪辑交接。

当前 Shotloom Agent 没有可自动操作剪辑时间线的画布工具。所有镜头和声音就绪后，按故事板顺序整理节点并创建最终剪辑执行 Note，写明镜头顺序、入出点、对白/旁白/BGM/拟音位置、转场和导出规格，然后引导用户从视频节点进入剪辑工作区完成组装与导出。没有真实编辑器成品或成功导出回执时，不得声称完整视频已经合成。

## Recipe 对应关系

- 剧本解析：`narrative-source-analysis`
- 人物、场景和道具档案：`video-character-design`、`drama-scene-extraction`、`drama-prop-extraction`
- 忠实故事板：`drama-shot-planning`
- 元素一致性图：`script-element-reference`
- 单镜构图、复杂动作和高清定帧：`video-shot-storyboard`、`video-action-sequence-board`、`video-frame-extraction`
- Seedance 连续镜头：`script-seedance-shot`
- 非 Seedance 兼容回退：`video-clip-generation`
- 声音生成与后期执行单：`video-audio-design`、`video-audio-production-sheet`

## 依赖与完成前评估

真实依赖为：剧本来源 → `Final_Video_Spec.md`；剧本来源 + 成片规格 → 故事板；故事板 + 成片规格 → 元素 Prompt Draft；已确认元素草案 → 元素图；真实元素图 + 故事板 + 成片规格 → 镜头 Prompt Draft；已确认镜头草案 + 真实元素图 → 视频；故事板 → 声音；真实视频 + 声音 → 剪辑执行单。

完成前逐项核验：剧本覆盖无遗漏，台词和顺序未改写；规格、故事板和两批 Prompt Draft 都有真实用户确认；上传资产没有重复生成；所有生成节点使用唯一匹配 Recipe；元素图和视频任务真实成功；每镜参考输入覆盖实际身份、场景、道具与动作风险且 prompt 写明输入职责；对白、旁白、音乐和字幕没有串轨；未完成的剪辑或导出在最终回复中明确列为下一步。
