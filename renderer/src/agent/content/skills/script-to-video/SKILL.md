# 剧本生视频（需上传剧本）

这个 Skill 只处理已经存在的剧本，不把一句创意、故事梗概或小说章节假装成完整剧本。首先检查本轮附件、用户明确引用的画布文本节点和素材库事实；若没有可读取的剧本正文，调用 `ask_user_question` 请用户上传 PDF、图片或文本剧本，或指定已有文本节点。不要因为内部字段缺失重复询问已经明确的信息。

读取剧本后先用一句话忠实概括故事，不改写台词、动作结果、场景顺序和结局。图片或扫描 PDF 中无法可靠识别的内容应指出具体缺页或模糊位置，不得补写。用户已提供的角色、场景、道具、音色、图片、视频和音频必须优先复用：先用 `canvas_list_nodes` 核验真实资产，需要放回画布时通过 `canvas_create_node` 的 `place_asset_on_canvas` 类型创建真实素材节点，再用 `canvas_connect_nodes` 建立真实输入边；已上传且可直接绑定的元素不编写生成 Prompt Draft，也不重新生成。

这是多阶段制作，只用 Production Plan 保存阶段、工作项、真实 `runtimeRefs` 和进度。计划是持续更新的工作依据，不是停止条件。用户明确要求逐阶段审阅时才在指定阶段暂停；否则在本轮授权范围内按依赖连续推进，不因规格、故事板或 Prompt Draft 已写好就主动结束。只有缺失信息会造成显著不同结果、需要权限确认，或用户要求审阅时才提问。用户已确认的偏好应沿用到相关后续阶段，不重复索取授权。

## 画布执行协议

- 进入一个阶段时先用 `canvas_list_nodes` 的 `timeline` 或 `summary` 掌握相关节点；已知剧本、规格、故事板、元素或镜头节点后改用 `canvas_get_node` 局部读取。只有需要从素材库取回资产时才使用 `full`。
- 每个生成节点分别通过 `canvas_create_node` 创建；后续直接使用成功回执里的真实 `nodeIds`。配置修订使用 `canvas_update_node`，输入依赖使用 `canvas_connect_nodes`，并显式填写当前模型契约要求的 `role`、`slot` 和节点 `inputMode`。
- 先由本 Skill 根据剧本确定阶段、`element_id`、`shot_id`、依赖和故事顺序，再调用 `canvas_layout_nodes` 整理明确的节点集合。布局工具不会从标题、节点类型或文案猜测故事结构，不能用无输入语义的连线表达先后顺序。
- `plan_canvas` 到真实节点与输入边就停止。`plan_and_execute` 只用 `canvas_start_generation` 启动当前依赖已经满足的节点，保存每次 task 回执，再用 `inspect_tasks` 核验终态；不得把已提交、运行中或布局完成当成媒体完成。
- 用户通过 `/script-to-video` 要求从剧本制作视频时，至少把已确定的视觉资产和逐镜视频落成可执行的画布节点。关闭“允许 Agent 运行节点”只阻止启动生成，不阻止创建、配置和连接节点；不要因此把已有制作计划的 `plan_only` 当成停止制作的理由。若用户这轮只要求分析或审阅方案，则按该明确范围处理。
- 任一写入发生 revision 冲突时重新读取相关节点，只修复尚未成功的动作；已经返回成功 `nodeIds`、`edgeIds` 或 `taskIds` 的操作不得整批重放。

## 原生阶段

### 1. 剧本准备与成片规格

把剧本来源放到画布或引用已有真实节点，并建立一句话故事总结。成片规格记为 `Final_Video_Spec.md`，写入本阶段的制作计划描述并在回复中完整给出，至少覆盖：标题、内容类型、目标观众、画幅、预计总时长、单镜最大时长、视觉风格、主色、输出语言、对白语言、是否需要旁白、音乐方向、目标清晰度和模型偏好。任何会显著改变镜头数量、节奏或交付成本的缺失规格，由 Router 一次性集中询问。

规格形成后写入计划并继续设计故事板；仅当缺失规格确实影响制作方向且无法用已有信息合理确定时集中提问。用户要求先审规格时展示摘要并暂停。

### 2. 忠实故事板

故事板必须以剧本和当前 `Final_Video_Spec.md` 为唯一事实依据。可做的技术编辑只有：按候选模型真实时长与动作能力把一次无法完成的内容拆成连续镜头，以及补充专业镜头语言。不得增删剧情、改写逐字台词、改变动作结果或调换场景顺序。

先建立稳定元素清单：角色、关键生物、场景、关键道具和音色分别拥有唯一 `element_id`。角色描述记录脸型、五官、体型、发型、服装与剧情允许的状态变化，并记录声音、语速和音色；场景描述记录空间结构、重要物体的位置与朝向、表演区域和光向；道具描述记录外观、材质、尺寸、状态及持有关系。用户指定的参考资产必须与真实可见内容一致。

逐镜使用唯一 `shot_id`，每镜写明：所用场景和元素 ID、剧情动作、逐字台词或旁白归属、景别、角度、摄影机运动、起始状态、结束接点、目标时长和音频层。默认一次视频节点对应一个连续长镜头；真实切镜、换场或不连续时间拆为不同 `shot_id`。不要把多个 `shot_id` 合并成一条总提示词；只有当前模型目录明确支持多镜叙事且用户明确要求时，才允许在单节点内使用内部剪切。

声音层至少说明全局音乐方向；剧本存在对白或旁白时，分别记录逐字内容、说话者、声音/语气和覆盖镜头。故事板写入本阶段的制作计划描述，逐镜工作项随后通过 `runtimeRefs` 绑定真实视频节点。故事板确定后，读取 [逐镜状态与跨镜接力](references/shot-continuity.md)，把镜头的进入、离开及相邻承接状态写进相应工作项，再继续写元素提示词；用户要求审阅故事板时才暂停。

### 3. 元素图 Prompt Draft

在创建或启动任何缺失元素图的生成节点之前，先为每个待生成元素编写完整 Prompt Draft。中文界面或中文输入时使用中文提示词；对白仍遵守 `Final_Video_Spec.md` 的输出语言。每份草案必须包含：资产类型、`element_id`、完整 prompt、推荐模型、模式、画幅、分辨率、真实参考输入及每项输入的约束职责。

开始写场景、道具或分镜静帧的 Prompt Draft 前，调用 `skill` 加载 `visual-prompt-craft`，按需读取 `visual-prompt-craft/references/image-direction.md`，由它约束可见细节、空间与参考职责；人物身份板另加载 `character-board`，并以剧本事实、已确定造型及真实参考图写完整外观。先确定当前图片是身份板、空场板、道具图还是单格分镜，再写对应的可见画面，不把一份通用画质词套到全部图片。这里的图片方法不改变 `character-board` 的四区域版式。本 Skill 的成片规格和节点执行顺序继续生效。

图片 prompt 只描述物理可见内容，用自然语言写出项目画风、主体身份或空间锚点、构图、光源、材质及当前姿态。不要解释角色动机，不要模仿在世艺术家的独特风格；配色从成片规格和已有参考获得，不强制固定比例或通用色调。需要准确画面文字时明确原文和位置；关键元素资产本身不生成无关文字。

缺少可复用的具名人物身份资产时，先调用 `skill` 加载 `character-board`，按其造型、角色板与提示词规范写人物元素图 Prompt Draft；本 Skill 仍负责节点创建和视频制作。场景和道具只建立下游确实使用的视觉依据，不为了凑数量生成。

将整批元素 Prompt Draft 写入对应工作项的 `prompt`，并继续创建、配置本轮范围内的图片节点。用户要求先审草案时展示完整内容并暂停；用户提出修改时更新受影响草案和节点，未受影响部分继续复用。

### 4. 元素资产生成

对用户未提供的元素创建图片生成节点，可按需参考 `script-element-reference` 提示词模板。读取单次模型能力快照：优先选择已配置、能接收本图必要参考且满足版式和清晰度需求的图片模式；只有所选模式真实提供清晰度参数时才请求 2K，否则使用目录声明的实际规格并在 Prompt Draft 中如实标注。如果该模型不可用，选择兼容图片模型，并向用户披露会影响身份、画风或规格的替代差异。模型与模式不得仅凭名称猜测能力，也不能把不受支持的参数写进 config。

`plan_canvas` 建立已确定的真实节点、prompt、model、`outputSpec` 和输入边，不启动任务。`plan_and_execute` 在用户已开启节点运行权限时启动当前无依赖阻塞的元素节点，并使用 `inspect_tasks` 等待真实完成。全部元素完成后核验身份、服装、材质、场景结构和道具状态；失败项只修复回执指出的问题。记录本阶段真实结果并继续下游；仅在用户要求审图、结果有必须由用户决定的方向问题，或权限边界要求时暂停。

### 5. 镜头视频 Prompt Draft

逐镜编写视频 Prompt Draft。只配置画布时，可依据剧本和已确定的资产设计先写完整草案并配置下游视频节点；真正启动视频前，再对照上游图片的真实成功输出修订。每份包含：`shot_id`、使用的元素资产、每项参考输入职责、完整 prompt、推荐模型和模式、画幅、时长、分辨率及音频要求。只有镜头包含人物进出、转身、交接、施法、多人走位、连续运镜或其他跨姿态动作时，才分别建立时间板与镜头板 imageGeneration 节点，并把它们作为普通参考输入；静态或低风险镜头直接使用角色/场景资产和清晰的动作 Prompt，不为凑流程生成空洞分镜板。模型容量不足时只减少实际传入的参考，并将缺失参考的已确认事实写回 prompt 和降级记录。

写视频镜头或创建、配置任何视频生成节点前，必须调用 `skill` 加载 `short-drama-video-prompt`，按需读取它的 Prompt 结构、参考清单、模型路由和质量检查，把内容写到可拍摄的动作链、机位、空间变化与结束接点；即使用户只说“生成视频”或只给了剧本，也必须加载，不得凭通用模板直接创建视频节点。同时读取 [单镜视频提示词与生成核验](references/video-prompt-and-review.md)，落实逐人物的表演、听者反应、道具受力与分镜参考的反宫格约束。按 [逐镜状态与跨镜接力](references/shot-continuity.md) 核对本镜进入与离开状态，不把前镜尾帧固定当作每镜首帧。

先通过 `inspect_model_catalog` 选定本镜实际可用的模型、模式与参考槽位，再定提示词格式。目标模型为 H3 时读取 `short-drama-video-prompt/references/h3-routing.md`，严格按该模式的字段与引用标签组织；选择 Seedance 时写中文自然语言的镜头、人物、空间、动作过程与声音，只有已确认的接入方式支持时才使用专有引用标记；其他模型遵循其真实能力，不冒用 H3 或 Seedance 格式。每个视频 prompt 都要指明实际连接的角色、场景、时间板和镜头板分别锁定什么，并把两板的不同信息编译进当前镜头：时间板转成动作先后与动线，镜头板转成构图、视线与叙事重点。旁白、原生对白、后配和画内文字按所选模型能力及成片规格分别处理，不凭固定括号语法假设模型一定能生成。负面约束只针对本镜最可能发生的身份、口型、道具、格线或媒介漂移，不用统一长串覆盖正面动作描述。

需要多节拍时按自然发生顺序描述；当所选模型适合时间区间且本镜确实依赖明确的动作或声音节拍时，可用覆盖完整目标时长的少量连续区间，不能机械套用相同秒数。需要真实切镜则拆成多个节点。将整批镜头 Prompt Draft 写入对应工作项的 `prompt`，并继续创建和配置本轮范围内的视频节点。用户要求先审镜头草案时展示完整内容并暂停。

### 6. 剧情镜头生成

创建视频生成节点时，优先选择能接收本镜关键人物、场景、分镜或运动参考且满足声音和时长需求的已配置模型，再按目录声明的实际规格请求输出，可按需参考 `script-seedance-shot` 提示词模板。代际新旧不能替代输入能力判断。每镜时长以动作、逐字台词、停顿和模型可用档位共同决定，不能把目录默认值套给全部镜头。所选模型不可用时，在能力快照确认后选择其他兼容模型；若替代会失去参考图、对白、音频或分辨率能力，必须先披露交付降级。

每个视频节点连接当前镜头真实需要的元素图片、时间板、镜头板或音色资产，prompt 明确映射输入职责。两板只作为普通参考，不能接 `firstFrame`/`lastFrame`；只有模型明确支持且另有干净起止帧时才使用首尾帧模式。按照 [单镜视频提示词与生成核验](references/video-prompt-and-review.md) 读回节点实际配置；同类镜头存在会导致整批返工的共同风险时先核验代表镜，再继续运行其余镜头，不因此增加用户未要求的审批。等待所有任务真实完成，逐镜核验剧情、身份、台词、动作、空间和首尾接点；不能用已提交或运行中冒充完成，也不能只凭成功回执声称已审片。记录镜头结果，按本轮目标继续声音与剪辑交接。

图片输入的视频内部适配由运行时自动完成，不规划或创建额外的内部预处理节点。

### 7. 声音与剪辑交接

依据故事板生成对白、旁白、音乐和拟音。存在兼容音频模型时使用 `video-audio-design`；不存在时创建 `video-audio-production-sheet` 文本节点，明确它是声音后期执行单而不是已生成音频。用户已上传音色参考时，将真实音频输入绑定到相应角色，不能用文字说明冒充连接。声音节点或执行单就绪后继续整理剪辑交接；用户明确要求试听或审阅时才暂停。

Shotloom 的画布工具不直接操作剪辑时间线；剪辑工作区的 Agent 拥有独立时间线工具。所有镜头和声音就绪后，按故事板顺序整理节点，把最终剪辑执行单写入本阶段的制作计划描述并在回复中完整给出，写明镜头顺序、入出点、对白/旁白/BGM/拟音位置、转场和导出规格，然后引导用户从视频节点进入剪辑工作区完成组装与导出。没有真实编辑器成品或成功导出回执时，不得声称完整视频已经合成。

以下模板仅提供方法和示例，按需读取、调整或组合。没有匹配模板时直接编写提示词，不得因此限制制作范围。

- 元素一致性图：`script-element-reference`

- 非 Seedance 兼容回退：`video-clip-generation`
- 声音生成与后期执行单：`video-audio-design`、`video-audio-production-sheet`

## 依赖与完成前评估

真实依赖为：剧本来源 → `Final_Video_Spec.md`；剧本来源 + 成片规格 → 故事板及逐镜连续性；故事板 + 成片规格 → 元素 Prompt Draft；元素草案 → 元素图；已确定的资产设计 + 故事板 + 连续性 → 可配置的视频草案与节点；真实元素图 → 启动前复核视频草案；镜头草案 + 所需真实元素图 → 视频；故事板 → 声音；真实视频 + 声音 → 剪辑执行单。

完成前逐项核验：剧本覆盖无遗漏，台词和顺序未改写；用户明确要求审阅的内容已得到确认；上传资产没有重复生成；所有生成节点具有符合内容和输入职责的完整提示词；元素图和视频任务真实成功；每镜参考输入覆盖实际身份、场景、道具与动作风险且 prompt 写明输入职责；对白、旁白、音乐和字幕没有串轨；未完成的剪辑或导出在最终回复中明确列为下一步。计划有未完成项时继续处理可执行工作，确有阻碍则据实说明，不能把提问当作普通阶段的收尾。
