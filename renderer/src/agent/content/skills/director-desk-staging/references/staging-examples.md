# 六类事件的编排与核验

案例描述导演选择，不是可直接提交的工具 JSON。按快照中的实体、目录能力和用户时长实施；无需为了套案例另建文档或审批步骤。

| 事件 | 编排方法 | 最容易遗漏的核验 |
| --- | --- | --- |
| 追逐与掉头 | 先建立双方相对位置、追逐方向和障碍，再安排减速、转身、重新加速。需要稳住画面方向时，选择自由机位路径或关闭旋转继承的跟随偏移。 | 掉头前、中、后双方方向与距离；角色是否重复转身；机位是否绕轴、穿墙；步态有无重启。 |
| 双人对白 | 先用同框建立关系，选择保留双人表演或切过肩/反打；反应随信息到达展开。固定机位摇看 A、B 时改变观察点，而非误用主体跟随。 | 两人左右与视线匹配；肩部遮挡；关键手势是否入画；反打的光源仍位于原世界方向。 |
| 发现线索 | 建立人和线索的空间关系，让注意力先发生变化，再通过构图、摇摄或插入揭示线索，并留下决定的结果。 | 线索是真实道具且可辨；视线落点正确；遗留 targetPath/targetId 没有把机位拉回旧目标；插入镜不制造空间跳跃。 |
| 道具交接 | 明确谁持物、哪只手、接近与接触的时点，以及接收者承重后原持有者松开的状态。依当前工具能力设置绑定或位置，不靠改名、切镜假装完成。 | 接触前、交接时、分离后手与物的位置；道具没有悬浮、复制或瞬移；下一镜持物者与持物手一致。 |
| 碰撞与恢复 | 将接近、接触、失衡、支撑、落地和恢复串成因果链，路线与动作同时安排。机位让受力关系和后果可见。 | 接触距离、受力方向、重心与落地；不能只播放 fall 就称为发生碰撞，也不能把穿模藏在切点。 |
| 动物追逐 | 先查询动物资产实际支持的动作与姿态，再安排路径速度、四肢相位、支撑和重心。能力不足时明确交付为路线预演，并说明尚未实现的步态。 | 不能套用人体动作目录或周期；模型位移不等于奔跑；核验整个步态周期及转弯、停止，而非只看一帧。 |

相邻时间取样用于比较变化，不能把有限静帧说成已经验证完整运动或声音。最终说明实际改了什么、看到哪些时刻、哪些细节仍缺证据。
