# 3D 导演台创作与画面核验

本 Skill 负责导演判断和完成标准。实际可执行操作、字段、素材和 ID 以当前 `director_desk_snapshot` 与 `director_desk_catalog` 为准；不要把其他导演台产品的方法当作本工程的能力。

## 按任务选读

- 设计分镜、构图、光影、表演或跨镜连续性时，读取 [镜头设计](references/shot-design.md)。把导演目的落成观众能看到的信息变化，镜数与时长由事件决定，不按固定间隔切镜。
- 设置跟随、摇摄、焦距、路径、转身或动作叠加时，读取 [相机与动作合同](references/camera-and-motion.md)，先核对控制优先级与当前写入格式。
- 追逐掉头、双人对白、发现线索、道具交接、碰撞恢复或动物运动时，读取 [编排案例](references/staging-examples.md)，按真实素材能力改编，不机械复制时长或坐标。

## 把需求变成可拍的场景

- 先理解用户要观众看到的事件、人物关系、空间关系、镜头重点和时间节奏，再决定需要改哪些角色、道具、机位、灯光或戏段。保留用户指定的动作、台词、时间和构图；没有必要时不改动已有内容。
- 尺度基准：1 单位 = 1 米，素材原点在底面中心，`position` 的 y 即落地高度——墙、柱、柜这类站在地面上的物体，底部贴 `y=0` 才不悬空。人物默认身高 1.75 米，门框净高 2.2 米，先用这几个已知量换算高度、宽度与通行净空。`director_desk_catalog` 按 group／query 筛出的条目带 `defaultSize`（默认尺寸），不必先摆放再测量。
- 角色与道具的位置要服务于镜头中的关系：谁面向谁、谁能碰到什么、角色是否站在地面或坐在座面上、行动终点是否落在目标附近。只填坐标而不看画面，不能证明互动成立。
- 先在素材目录找语义匹配的对象。箱子可以用箱子，不能把外形不相关的道具改名冒充用户指定的物体。目录缺少关键物体且现有命令无法制作时，明确说明能力缺口；抽象几何只适合用户接受的示意布景或远景体块。
- 对建筑、墙体、门窗、楼梯及复杂道具，先确定外轮廓、比例、开口、部件相接关系和人物尺度，再检查细节。调用 `inspect_model` 看多视角、尺寸和部件；模型单独好看仍不能证明它在场景里放得正确，随后要看含人物与机位的场景帧。

## 机位与时间线

- 先判断镜头是要交代空间、突出表演，还是展示物体。选择景别、角度和视线方向，让重要动作无遮挡且观众能读懂；优先调整机位与构图，避免仅为填满画面而挪走角色。
- 动作、路径和切镜应围绕可辨认的事件节拍安排。走位优先用一次声明的路径（批量的 `set_path`）写清每个时点的位置，让速度由时间点决定，而不是靠反复微调单点漂移。路径结束时检查角色最终朝向；转身、接近、交接、坐下等动作要在画面中成立，不能只凭时间线片段名判断。
- 时间线修改后选有意义的时点核验：动作前、动作中、动作后，以及切镜两侧。优先用 `render_preview_sheet` 一次比较相邻时点，再用 `render_preview` 放大可疑帧。拼图每一格都要看；一张好看的单帧不能证明整段连续。

## 核验与修正

- 每次快照中的 `sessionId` 与 `revision` 是一对写入依据。批量修改分别传入 `expectedSessionId` 与 `expectedRevision`；重新打开导演台后 revision 可能变小，这不是内容丢失的证据。会话变化或版本冲突时重读快照并核对受影响对象，利用 `revisionDiff` 定位增删改；不要只换版本号重放旧批次。
- 写入前按目录核对 `batchOperations` 的合法字段、素材 `parameters` 的 min/max/choices 和 `patchFields` 的类型与范围；`valueTypes` 提供真实 JSON 格式。`AnimatedNumber` 是数值或 `{keys:[{time,value}]}`，`focalKeys` 才直接使用数组。尺寸越界需重新设计或选素材；拿不准可用 `validateOnly:true` 预检。失败时依据具体项和回执合同修正，不原样循环重试。
- 数值写成不加引号的 JSON number，向量使用平铺的三个数。失败时核对 `issues` 的字段路径或 `receivedEdit` 的实际值与类型，再按目录示例修正；不要从一次拒绝推断“所有数值必须用关键帧”，也不要并行猜测多种格式。合法输入仍失败时读回当前快照，保留原始失败项说明问题。
- 优先让代码测量几何：用 `director_desk_query` 的 `entity_relations` 查询指定时刻的相对方向、距离、机位中心视线遮挡与接触锚点。用批量 `place_on_surface` 落面、`seat_on_surface` 对齐显式座面锚点、`align_facing` 面向目标、`align_surface` 贴合表面。这些宏支持内置人物与道具；按回执处理不支持的模型。几何测量和中心视线都不能替代画面核验。
- 批量修改可带 `autoPreview: { timesSec: [0, 2], plan: true }`，成功后直接查看回执中的真实预览附件。若 `applied: true` 且有 `previewErrors`，修改已经生效，只重试取帧，不要重做整批写入。
- 写入回执证明命令被接受，场景文档证明结构，`spatial_check` 证明它采样范围内的机械问题，`render_plan` 的俯视平面图证明布局与路线是否对得上参考，真实渲染帧才支持关于构图、遮挡、光影、姿态和外观的判断。这些证据不能相互替代。
- 用预览检查主体是否入画、比例与朝向是否合理、脚与座面是否接触、道具是否穿墙、建筑开口是否可用，以及相邻时点是否突然跳变。发现问题时定位对应时间、实体或机位，做针对性修改，再取帧复查。
- 如果当前工具不能提供足够证据，就明确说出尚未核验的部分。身份特征或关键空间关系仍明显错误时，不要宣称完成。用户要求交付视频时，先核验预演效果，再启动导出；不要靠反复导出视频检查场景。

最终回复简要说明实际改动、看过的画面与仍存在的问题。不要引用未看过的帧，也不要把参考项目的实现方式写进用户的工程。
