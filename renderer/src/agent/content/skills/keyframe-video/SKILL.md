# 关键帧动态编排

先读取视频模型能力，确认它实际接受哪些输入角色以及允许多少张图片。当前 Agent 仅公开 `referenceImage`，并没有尾帧角色，因此不能把两张参考图解释为强制首尾帧。

## 选择路径

- 单一起始帧：若一张稳定起始画面已经核验为融合完整，可单独约束低风险镜头；提示词补足动作过程和运镜。身份、产品、空间或动作风险没有被该帧充分表达时，仍需加入模型支持的相关依据。
- 明确收尾：在视频 prompt 中描述可执行的最终姿态与画面状态，不能依赖代码中不存在的尾帧锁定。
- 多个关键姿势：动作含有不可省略的阶段时，先制作关键姿势，再依据模型实际图片上限拆成若干连续视频节点，每段只连接被当前模式支持的参考。
- 多宫格转视频：先把目标格重建为独立高清关键帧，禁止直接把整张宫格当作单镜起始帧。

## 执行顺序

1. 锁定同一连续镜头的主体、场景、时长、动作阶段和摄影机轨迹。
2. 建立必要的关键帧节点，逐帧说明时间位置、姿态、构图以及必须保持的身份与空间特征。
3. 通过 `video-frame-extraction` 生成或提取高清独立帧，并核对主体和构图连续性。
4. 等待关键帧任务完成并检查真实结果中已融合的约束；把主关键帧作为 `referenceImage` 接入视频，同时为仍未清楚表达且影响成片的身份、产品、场景或动作风险补充参考。内部输入适配由运行时自动完成。
5. 用 `video-clip-generation` 创建连续镜头，写清动作节拍、主要运镜、环境响应和结束状态；提示词必须逐项说明各参考输入的约束职责，只使用当前镜头确实需要且能力快照允许的图片。
6. 当动作过程或切镜超出单次生成能力时，在自然动作接点拆段，不能靠加速或堆叠 prompt 强行塞入。

先用 `keyframe-scene-script` 规划关键帧及过渡，再按真实节点类型加载图片或视频 Recipe，并把相应 `recipeId` 写入节点。

完成前评估：关键帧顺序正确，身份与场景连续，动作阶段无缺漏，每个视频节点只有一个连续机位，输入数量符合模型能力，而且每项高风险约束都有直接视觉依据或已核验融入主关键帧。
