# 全流程影像制作

先辨认输入是创意主题、小说/长篇章节、故事梗概、完整剧本、现成分镜还是已有素材，再确认用户最终需要分析、剧本、分镜、关键帧、视频或完整生产。只能从现有成熟度推进到下一项必要工作：不把小说直接当分镜，也不重做已完成的剧本和镜头表。若用户粘贴完整内容却没有清楚指令，应确认只规划还是规划并执行。规划前先在内部提取跨镜视觉实体并合并别名，评估复用、复杂动作、换机位、身份特写和严格构图风险，并且不为这份判断额外创建表格节点。

## 制作阶段

1. 文本基础：小说或长篇来源先形成忠实原作的结构解析，再按成片规格转换为剧本；故事大纲补全场次、冲突和可见行动；完整剧本直接检查并拆镜；完整分镜则进入视觉制作。只补用户交付所缺的层次，不机械生成每一种文档。
2. 身份与空间资产：对跨镜复用或身份敏感的视觉实体先建立文字档案，再制作单张电影级角色设计板。总板应通过主立像、完整全身转面、少量头部角度研究、剧情核心情绪肖像与服装配件拆解集中身份，并使用中性背景、充足留白和克制的不对称构成。视觉实体不仅是有姓名的人物，还包括反复出现的非人角色、怪物、拟人道具、群体角色和承担叙事功能的生物；例如“纸人”“纸扎人”“纸扎人队列”应合并为同一实体。剧情场景里的单张人物镜头只能作为关键帧，不能冒充角色板。其他资产仅在存在类型匹配 Recipe、兼容模型且下游确实消费时创建。
3. 镜头设计：按叙事功能拆镜，只要出现真实切镜、机位变化或不连续时间，就应建立多个视频节点。较长内容可制作分镜总览；普通镜头用单镜动作构图；连续表演、明显位移、道具交互或动作爆点使用六格动作序列检查起点、接触、主动作、结果和收束。当前没有多机位覆盖专用 Recipe，不能另造此类资产。
4. 高清定帧：只为构图、身份、动作或空间连续要求高的镜头创建。有真实多宫格输入时，`video-frame-extraction` 可以重建指定格；没有宫格时，它也可以生成独立帧，或通过 `video-shot-storyboard` 设计构图，但不得把独立生成描述为“提取”。
5. 连续视频：每个视频节点只承载一次模型调用能够连续完成的镜头，明确起始状态、动作演变、主要运镜和结束状态。
6. 声音内容：按用户目标建立对白、旁白、环境声或音乐节点。没有兼容音频模型时，改为文本形式的声音后期执行单，并明确它不是已生成音频。
7. 画布整理：使用现有布局能力按镜头顺序排布，不创建代码中不存在的时间线、合成器或汇总节点。只有生产范围为 `plan_and_execute` 且用户设置允许时才启动生成。

`plan_canvas` 必须创建完整且可执行画布：每个已经确定的连续镜头都对应真实视频节点，必要的身份、空间、动作和关键帧也有真实上游节点；节点填写完整顶层 prompt/model/recipeId/outputSpec，并预先建立能够确定的输入边，但不启动任务。不得用一篇流程说明来代替真实节点。

`plan_and_execute` 按依赖阶段执行：只创建并启动当前已经具备输入的节点，等待真实输出成功后再继续下游。后续节点可以先规划，但在依赖媒体完成前不能运行。视频输入内部适配由运行时自动完成，不规划额外预处理节点。

## Recipe 对应关系

- 原作解析、剧本转换：`narrative-source-analysis`、`screenplay-adaptation`
- 创意框架：`video-creative-outline`
- 导演镜头表：`video-storyboard-script`
- 跨镜角色档案：`video-character-design`
- 角色电影开发总板：`video-character-turnaround`
- 全片分镜总览：`video-storyboard-grid`
- 单镜动作构图：`video-shot-storyboard`
- 复杂连续动作六格板：`video-action-sequence-board`
- 多宫格高清定帧或独立帧：`video-frame-extraction`
- 参考锚点连续镜头：`video-clip-generation`
- 配音、音乐与拟音：`video-audio-design`
- 无音频模型时的声音执行单：`video-audio-production-sheet`

## 规划和连续性规则

- 共享资产应复用，不能为每镜重复创建人物与空间档案；但身份参考和动作构图承担不同职责，人物模卡不能替代复杂动作分镜。
- 先按名字、代称、外观和叙事功能归并同一视觉实体，再判断跨镜使用；不能因为没有姓名、不是人类、作为群体出现或被描述成场景元素而漏掉。
- 跨镜出现或外观一致性影响剧情的实体需要标准模卡；只出现一次但承担关键动作、身份特写或核心威胁的实体也属于身份敏感对象。只有背景干净、同一实体多视角且身份稳定的图片才能标记为角色板。
- 主关键帧是构图及起始状态锚点，但不要把它当成所有视觉约束的通用替代品。逐镜评估身份风险、多主体关系、空间结构、关键产品或道具和复杂动作：真实关键帧已经核验融合完整且风险低时可以单独输入；身份不清、多人物需要分别锁定、场景或产品精度影响叙事、复杂动作需要额外依据时，按模型能力直连角色板、场景板、道具板或动作板。规划模式下关键帧尚无真实输出，仍应根据风险预建能确定的参考边，不能预设未来一定融合成功。
- 每项直连视频的视觉输入必须服务当前镜头，并在视频提示词中说明它负责的主体、身份、场景、道具、材质或动作，同时复述不可变化特征。不要按固定数量连接，也不要因为模型上限较高就加入无关、重复或冲突图片。
- 当输入来自角色开发总板，或主关键帧已吸收总板时，视频 prompt 要锁定五官、脸型、发型、身材比例、服装结构及细节，要求自然表情和符合人物的肢体动作，并抑制身份漂移、服装变化、画面闪烁和时序抖动。只有项目明确采用写实真人路线，才追加“超写实真人摄影质感、真实细腻皮肤纹理、电影级光影与高清电影质感”；半写实、动画、纸扎、怪物等内容应替换为自身材质描述，不能被这段模板真人化。
- 人物总板继承项目既定的写实、半写实或动画方向，不能默认真人化。供应商拒绝疑似真人输入时，停止相同重试，改用官方授权人物/虚拟人路径、具有明确肖像授权的素材，或保持明显风格化原创人物。不得通过模糊、马赛克、遮挡、拆分五官再重建等方式规避人脸审核，也不能处理明星、公众人物或未经授权的真人肖像。
- 简单动作且已有关键帧足够时可省略额外动作板；单一构图可说明时用单镜构图；动作包含多个关键节拍时用六格动作序列。默认不做十二格覆盖研究，避免为了展示机位制造无用资产。
- 普通连线只代表真实输入：媒体类型写入 `role`，参考/首帧/尾帧等业务语义写入 `slot`；先按模型目录设置节点 `inputMode`。独立镜头不串联，阶段次序由计划和布局表达。
- 模型只从一次完整能力快照选择，不硬编码名称。画幅、时长与清晰度写入 `outputSpec`，config 只包含当前模式支持的参数。若某模型不支持必要参考或交付规格，优先选择兼容模式或模型；若必须删除身份/构图输入、改变节点类型或用文档替代生成物，则属于交付降级，必须在过程和最终回复中披露。
- 所有生成节点加载唯一匹配的 Recipe 并携带 `recipeId`；Production Plan 的每个工作项绑定自己的真实画布节点，局部失败只修复回执明确指出的问题。

完成前评估：依据前面的内部风险判断检查真实画布，确认叙事完整，人物、非人角色、怪物、拟人道具和群体角色都有合适身份锚点，复杂动作拥有构图依据，六格动作序列在身份、持物、空间轴线和接触点上连续。逐个核对视频节点的视觉输入是否覆盖身份、场景、产品/道具和动作风险，并确认 prompt 映射每项输入职责。既不能让未经核验的单一关键帧代替所有约束，也不能堆叠无关参考；依赖无环，prompt 非空，没有孤立中间节点。任何声称由分镜提取的节点必须真实连接分镜图片；独立生成不能冒充提取。所有文档替代和缺失资产都应在最终回复中明确说明。
