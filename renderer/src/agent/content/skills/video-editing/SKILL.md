# 剪辑与成片核验

当前会话位于 Shotloom 视频剪辑工作区时使用本 Skill。它负责剪辑判断和质量标准；工具是否支持某项操作以当前运行时能力为准，不得把参考项目的方法名当成已实现能力。模型必须先读取真实项目，再决定剪点和修改范围。

## 先感知，再决定

- 首先调用 `video_project_get` 读取真实媒体、轨道、片段 ID、时间范围、播放头和当前工程状态。
- 需要判断画面内容、动作时机或字幕遮挡时，调用 `video_project_frame` 查看源视频帧；不能从文件名、时长、片段数量或经验臆测内容。
- 修改后调用 `video_project_get` 和 `video_project_diagnostics` 重新核对；需要验证合成效果时使用 `video_project_view`，并对改变位置调用 `video_project_frame`。源帧不包含字幕、叠层、转场或特效合成效果，不能把源帧当成合成画面证据。
- 无法读取或听到的部分必须明确说明不确定性，不得编造动作、对白、音乐节拍或视觉效果。

## 多素材组装与拼接

- 时间线上还没有的素材，先用 `video_project_media` 列出候选，再用 `video_project_edit` 的 `add_media` 引入。只使用该工具真实返回的 `materialId` 或 `nodeId`，不得凭文件名、节点标题或时长编造来源。
- `add_media` 与 `add_clip` 省略 `atSec` 时都追加到目标轨道末尾，所以按目标顺序一次提交多段即得到首尾相接的时间线；要插在中间时显式给出 `atSec`。
- 引入、排序和必要的裁切放在同一批次里提交，先 `validateOnly` 预检再正式写入。引入素材是可撤销的普通剪辑修改，不要让用户先手工把素材拖进工程。
- 拼接后必须用 `video_project_diagnostics` 核验接缝处没有空隙或重叠，再按下面的节奏标准决定是否裁切、变速或加转场。
- 素材已在工程中时工具会复用同一素材并在回执里提示，不要因此重复添加；`add_media` 丢弃音轨时也会明确说明，必须把这一点告诉用户。

## 画布格式与构图

- 用户要求抖音、竖屏、方形等成片比例时，先用 `set_canvas` 把画布设为目标尺寸（抖音竖屏 1080×1920），再对需要铺满的片段设 `fit: "fill"`（居中裁剪填满）。`fit` 缺省是留边显示 —— 只放大片段框而不声明 `fill`，画面仍会在框内留边，等于没有填满。
- 横屏素材放进竖屏画布只有两条路：留边（保留完整画面）或居中裁剪填满（裁掉两侧）。不要靠拉伸或反复缩放去凑画布比例。
- 切换画布格式不会自动改动任何片段，已有构图是用户之前的决定。只调整用户明确要求或交付确实需要的片段，不要整条时间线一起改。
- 转场和特效只使用工具 schema 枚举里的 key；回执报错会列出当前可用值，照它修正后重试，不要自创转场名或反复提交同一个无效值。

## 节奏与剪点

- 开头 1–3 秒优先呈现动作、人物或最强信息；用户明确要求慢节奏、叙事铺垫或留白时服从用户意图。
- 优先在动作落点、句子结束或自然停顿处切；没有转录或音频证据时，不要声称切在某句之后。
- 不要让所有镜头拥有相同长度。快切后保留必要的停顿；口播或叙述镜头连续超过约 7 秒时，评估是否需要切镜、景别变化或字幕节拍，但不能仅凭时长强制剪切。
- 默认硬切。转场只用于章节、时间或情绪变化；一条成片尽量保持同一转场家族，不能为了“丰富”在每个接缝堆转场。
- `video_project_edit` 的批次应先使用 `validateOnly` 预检，提交后核对真实回执。使用 `split_clip`、`trim_clip`、`remove_range`、`move_clip`、`close_gap` 等实际支持的操作时，保持片段 ID 和项目时间语义准确。

## 字幕、文字与画面

- 字幕一条只表达一个完整想法；默认放在底部安全区，避开脸、嘴、主体动作和画面 UI。背景复杂时改放顶部或增强对比度。
- 统一字幕样式，不要逐条制造互相冲突的字号、颜色和阴影。没有真实帧证据时，不得声称字幕可读或没有遮挡主体。
- 标题、贴图和文字叠层只有在补充观众无法从画面获得的信息时才添加；持续时间要覆盖真实阅读时间。
- 调色先解决素材之间的温度、曝光和对比度差异，再增加风格。高强度色温、色调、颗粒、暗角或模糊必须有明确目的，并在修改前后用真实画面核对。

## 速度与声音

- 变速服务于节奏或动作强调：慢动作突出动作峰值，加速压缩无关过程；未经用户要求不要改变对白速度。
- 变速会改变时间线时长且不会自动推动邻居片段。修改后必须运行 `video_project_diagnostics` 检查空隙和重叠，并按用户目标决定是否闭合空隙。
- 对音量、静音、音轨、旁白和音乐的判断必须基于真实项目状态或音频证据。没有听音、波形或工具回执时，不要声称声音衔接或混音质量已核验。

## 完成前核验、回看与导出

修改完成后按以下顺序核验：

1. `video_project_get`：确认目标片段、时长、轨道和播放头。
2. `video_project_diagnostics`：检查空隙、重叠、缺失媒体和其他错误级问题；有意保留的问题必须说明原因。
3. `video_project_frame` 或 `video_project_view`：查看改变位置、转场接缝、字幕可见帧、效果前后和最后一秒。
4. 用户明确要求导出时，才调用 `video_project_export`；只有返回真实成功结果和文件路径后才能报告已导出。用户取消保存时明确说明未导出。

最终回复只描述实际完成的修改、可核验的结果和仍受工具能力限制的事项。没有真实回执或视觉证据，不得声称完成或已检查。
