# MG 画外音动画生成器技能

当用户提供产品或包装图像、App/SaaS 截图、旁白脚本或音频、产品材料、真实产品、虚构品牌或概念产品简介，或者仅仅是一个主题，并且想要一个 MG 动画作为解释器、发布、演示、解释或抽象主题时，请使用这项技能。

本技能不强加默认视觉风格，也不将风格视为相互排斥的菜单。它从用户的输入、参考图像、旁白语义和知识库中推断出一个主要风格方向、最多两个支持的视觉模块和一个核心叙事结构。只有当几个方向都有效、产生的结果差异很大且没有明确的偏好时，才会要求用户进行选择。

可组合风格模块包括：

- **高级产品发布/产品界面演示**:适用于 AI 平板电脑、手机、耳机、智能硬件、应用程序、SaaS、AI 工具、车载系统和可穿戴设备。强调英雄产品展示、界面演示、工作流程进展和品牌关闭。
- **清洁 MG 产品解释器/信息可视化**:用于家用电器、家用产品、服务、数据解释、课程、工具和功能益处。使用抽象锚、信息卡、图形隐喻和连续桥。
- **UI/SaaS 功能演示模块**:用于输入栏、仪表盘、Bento 网格、按钮点击、状态反馈、多设备同步和 AI 处理流程。
- **生活方式家电解释模块**:用于家庭设置和舒适、空气、水、温度和节能的日常表达。
- **数据/进度/效率可视化模块**:用于大数字、进度条、KPI 卡、效率提升、完成检查和趋势变化。
- **虚构概念产品发布模块**:用于用户定义的产品名称或原创品牌。可以创建原创产品外观、原创用户界面和品牌终止卡，但不得模仿真实品牌。

产品图像和旁白并非总是必需的。当旁白缺失时，询问用户是想要屏幕副本、旁白，还是两者都要。这项技能遵循 “编写 H3 提示词并将其放在画布上等待批准，然后在确认后生成” 的工作流程；它不使用旧的 “静态分镜图像→多个 MG 剪辑→合成” 生产链。

## 全球命名规则

- 在本技能中，H3 生成的动态图像被称为 “MG 动画”。
- 最终可交付的内容称为 “最终 MG 动画” 或 “MG 画外音动画生成器输出”。
- 为 H3 编写的完整文本称为 “H3 提示文档” 或 “MG 动画提示”。
- 请仅在指代底层工具、文件格式、用户上传的素材或本技能之外的输出时使用 “视频” 一词。

## 工作流程

1. 识别输入：产品图片、真实品牌、虚构品牌或概念产品、App/SaaS 截图、画外音脚本、画外音、产品材料或纯粹的主题。
2. 解决关键决策：当旁白缺失时，询问是否要在屏幕上输入文本，以及是否需要旁白；当真实产品必须保持真实性但没有产品图像可用时，请求一个；当请求概念产品时，确认是否允许原始产品的外观和品牌标识。
3. 结合风格和叙事结构：推断一种主要风格，零到两个辅助模块，以及一个核心叙事结构。不要强制使用四种风格菜单，也不要对固定的流程进行硬编码。
4. 分析材料和复制：提取旁白含义、销售点、屏幕关键词、持续时间结构、产品外观、颜色、材料、标志、界面和必须保持忠实的元素。
5. 阅读知识库并撰写 H3 提示：在交付规格、产品设置、整体视觉风格、核心结构、定时镜头、文字运动、元素运动、过渡、旁白和音频指导中，根据需要使用参考资料作为真实信息来源和依据。
6. 将完整的 H3 提示词放在画布上的 Markdown 文档中，供用户审核或修订。
7. 不要在批准之前生成。当用户请求发生变化时，先更新画布提示文档，然后再次等待确认。
8. 在明确确认后，使用 H3 生成一个完整的、连续的 MG 动画。

## 输入规则

1. **参考图像 + 画外音**:分析两者并创建一个忠实的、画外音驱动的 H3 提示文档，然后将其放在画布上等待批准。
2. **无旁白的参考图像**:首先询问是否要在屏幕上输入文本，以及是否需要旁白；确认后，编写提示文档并将其放置在画布上。
3. **无参考图像的旁白**:根据旁白创建一个信息解释器、功能解释器、界面演示或抽象主题 H3 提示文档，然后将其放在画布上。
4. **既不要参考图像，也不要旁白**:首先询问是否要在屏幕上写文案，是否需要旁白；必要时还要询问主题方向、目标持续时间、宽高比、风格，以及是否允许使用虚构品牌或外观。

处理规则：

- 当脚本和音频都可用时，使用音频作为时序基线，文本作为语义参考。
- 对于只有音频的情况，先请用户提供逐字稿；没有逐字稿时只分析节奏、结构和可听线索，不编造台词。
- 对于只有拷贝的情况，估计拷贝的持续时间，并以秒为单位计划时间线。
- 使用参考图像时，要保留外观、颜色、材料、比例、标志、结构和关键识别元素。
- 如果没有产品图像，可以使用抽象主题符号、信息卡、UI/图形容器和视觉隐喻。如果用户允许概念产品，可以创建原创产品外观。

## 品牌和产品真实性规则

- **真实品牌/真实对象/用户上传参考**:保留外观、颜色、材质、比例、标志、结构、系统界面和关键识别元素。不要创造标志、模型、包装复制、系统界面或官方品牌素材。
- **虚构品牌/概念对象/用户定义名称**:当用户明确提供虚构名称、概念简介或原始对象简介时，创建其原始外观、界面和品牌结束卡。不要包含真实的品牌标志、真实的系统界面或真实的商标。
- **仅限类别，无品牌或参考图像**:使用抽象剪影、通用 UI、信息卡和图形隐喻。不要生成真正的品牌标志、特定模型或包装复制品。
- **中心对象的连续性**:当参考图像或概念对象存在时，将其作为整个作品的视觉锚点，并在开始和结束时回到它或主题卡。

## 风格组合规则

- 不要将风格视为相互排斥的。选择一个主要风格方向，零到两个支持模块，以及一个核心叙事结构。
- 主要风格设定整体氛围、背景、产品呈现和节奏。支持模块提供局部视觉方法，不能让作品在风格上显得零散。
- 从用户输入和语义中获取风格描述。关注氛围、空间、层次、材料、视觉载体和叙事节奏。不要假设默认风格或强制使用特定的调色板。
- 常见组合：
  - AI 平板电脑：以优质产品发布为主要风格，包括 UI/SaaS 演示和数据效率可视化。
  - 智能空调：以生活用品解释为主要风格，配备清洁 MG 解释和温控 UI。
  - AI 调度应用：以 UI/SaaS 功能演示为主要风格，采用清晰的 MG 和数据/进度可视化。
  - 虚构的智能硬件：虚构的概念 - 产品发布作为主要风格，包括高端技术发布和 UI 演示。
- 不要仅仅为了填写菜单就打断用户。如果用户已经指定了一个方向，如暗色高端技术、清洁生活方式、用户界面演示或舒适的家用电器，请直接使用这些组合。
- 只有当多个方向同样有效且其视觉效果会有显著差异时，才应该询问。

## H3 提示输出结构

为 H3 编写的最终提示词应优先考虑这种结构：

1. **生成规格**:持续时间、宽高比、风景/肖像、动画类型、是否包括旁白以及是否应该生成音频。如果存在，请保持用户指定的帧率，但不要依赖帧率来控制结果。
2. **产品设置**:产品类型、产品/品牌名称、真实或虚构状态、外观、核心功能、逼真的视觉元素，以及不得发明的内容。
3. **整体视觉风格**:背景氛围、构图、主题光照、UI 风格、纹理、视觉密度和整体感觉。这些都源于输入、参考和旁白语义，无需强加默认调色板。
4. **核心结构**:让知识库选择一个信息流、比较、处理、中心对象、时间线、仪表盘或聚合结构；不要每次都强制使用相同的箭头链。
5. **逐秒时间线**:对于每个片段，包括视觉内容、屏幕文本、旁白、元素运动和转场方法。添加镜头尺寸、摄像机位置、摄像机运动、主体行为、背景运动和声音（如有必要）。
6. **成片转场**:避免硬切和 PowerPoint 式开关。桥接段包含对象轮廓、屏幕边框、UI 卡、点、线条、循环进度、关键字形、设备连接线、进度条或完成检查。
7. **文本规则**:屏幕文本是 MG/UI/发布影片的设计元素，而非普通字幕。不要创建底部字幕栏或逐字显示完整的旁白。
8. **对象和品牌规则**:保留真实对象；允许原创虚构对象，不进行模仿；没有品牌或图像，仅使用抽象对象和通用 UI。
9. 音频指导：整体音乐风格、微妙的声音效果和禁止的音频元素。

## 高级产品发布结构

当请求是高级产品电影、技术发布、电子产品界面演示、App/SaaS 功能演示、AI 产品发布或产品英雄时，请优先：

```text
Hero opening → pain point / use case → AI or core system organizes information → feature interface demo → multi-scene / multi-device linkage → data result or completion state → hero product → brand end card
```

写作要求：

- 在开场时建立产品存在感：从黑暗中显现，用光线描绘边缘，照亮屏幕，然后添加轻微悬停或缓慢旋转。
- 让 UI 动态自然地从产品屏幕或产品周围的空间中生长；不要让不相关的素材独立浮动。
- 将每个功能部分视为工作流程中的一个步骤，而不是一堆孤立的销售点。
- 回到产品正面、产品英雄或最后的品牌终结卡。
- 当存在数据或完成状态时，使进度条、数字、完成检查和状态点从前面的 UI 元素连续变换。

## 清晰的 MG 产品解释器结构

当请求涉及电器、生活方式产品、服务说明、功能描述、数据说明、教育、课程或工具时，首选：

```text
Product/theme setup → pain point or need → core benefit breakdown → scenario experience / workflow demo → data or result proof → brand/theme closure
```

写作要求：

- 产品可能是象征性或抽象的，但核心类别必须保持稳定。
- 使用信息卡、点、线、图标、循环进度、UI 面板和关键词作为主要视觉语言。
- 每个屏幕上只显示一条核心信息，避免使用密集的小文本。
- 在相邻镜头之间设计一个桥梁，这样结果看起来就不会像 PowerPoint。

## 高端技术产品发布风格

适用于 AI 平板电脑、手机、耳机、智能硬件、SaaS、应用程序、AI 工具、车载系统和可穿戴设备。

根据用户输入、参考图像和旁白语义确定视觉方向。使用知识库选择背景、构图、材料、UI、图形和节奏，而不是应用固定的模板。

## 产品英雄和 UI 演示规则

- 当产品图像存在时，保留产品作为视觉锚点，并保留其外观、颜色、材料、比例、标志和关键组件。
- 当没有产品形象存在，但用户允许创建一个虚构的概念产品时，创建一个原始的产品外观、原始的 UI 和原始的品牌终止卡。
- 产品可能会从黑暗中浮现，被边缘光线勾勒出轮廓，缓慢旋转，照亮屏幕，并在开口处展开其界面。
- UI 运动应该自然地从产品屏幕、产品边缘、设备连接线或周围空间中产生。
- 结尾必须回到产品正面、产品英雄框架、品牌名称或主题结束语。
- 产品、用户界面、卡片、线条、数据和文本必须具有明确的因果关系。

## 相邻镜头的桥接规则

- 无论是优质的产品胶片还是干净的 MG 解释器，都必须在相邻片段之间指定一个桥梁。
- 清楚地说明前一个片段中的哪个元素将成为下一个片段中的哪个元素，过渡持续多长时间，以及摄像机如何移动。
- 推荐桥梁：一组杂乱的卡片被吸引到 AI 光环中并进行分类；功能卡向右延伸进入时间线；时间线节点飞出成为设备连接点；连接线流回屏幕并重新形成仪表盘；进度条收缩成完成检查；检查成为品牌端卡上的一个光点。
- 不要只写 “自然过渡”、“平滑切换”、“快速过渡” 或 “淡入/淡出”。

## 画布提示词 - 文档规则

- 生成 H3 提示词后，使用 `canvas_create_node(nodeType="textGeneration")` 创建提示词文档节点，把完整 Markdown 写入节点 prompt；建议标题为“产品或主题 + MG 画外音动画生成器提示词”。
- 文件必须包括制作总结、真实/虚构状态、输入材料、持续时间、宽高比、风格、旁白状态、音频生成状态、核心结构以及为 H3 准备的完整提示。
- 在用户批准之前，不要对视频节点调用 `canvas_start_generation`，也不要生成最终的 MG 动画。
- 当用户请求发生变化时，先修改提示文档，将更新后的版本放在画布上，然后再次等待批准。
- 在明确批准后，使用画布中确认的提示词调用 H3 并生成 MG 动画。

## 默认音频引导

默认情况下，在 H3 提示词中输入克制、现代、清洁的低频高端电子音乐。添加非常细微的卡滑音、AI 通知音、设备连接音、完成音和结束音。不要歌词、嘈杂的声音、压倒旁白的重节拍或夸张的卡通效果。没有旁白，音乐和细微的声音效果可以承载更多节奏，同时保持克制和清洁。

## H3 生成规则

- 默认情况下，使用 H3 生成一个完整的、连续的 MG 动画，但只有在用户批准 H3 提示文档后才能使用。
- 不要默认生成静态分镜，将作品分割成多个剪辑，或者合成多个剪辑。
- 如果旁白太长，首先建议缩短它，或者询问是否要将其分割成多个 MG 旁白动画；未经确认，不要将其分割。
- 不要默认添加普通的底部字幕。屏幕上的文本仅限于关键词、短语、步骤标签、数据标签、UI 标签、产品发布标题或品牌短语。
- 在没有旁白输入的情况下，首先确认用户是否想要屏幕副本，以及是否需要旁白。在确认之前，不要编写最终的 H3 提示文档或生成最终的 MG 动画。
- 在 H3 提示文件中强调，结果应该像一个完整的产品 MG 动画或优质产品界面胶片，而不是一个静态图像的幻灯片放映。

## 禁止的行为

- 在用户批准 H3 提示文档之前，不要调用 H3 生成最终的 MG 动画。
- 不要跳过提示文档的画布审批步骤。
- 不要使用旧的 “静态分镜审批→多个 MG 剪辑→合成” 链条。
- 不要把整个旁白变成底部字幕。
- 不要将结果制作成产品图片幻灯片或类似 PowerPoint 的硬剪辑序列。
- 有产品图片时，不要忽视产品的真实性。没有产品图片时，不要创造真实的品牌、真实的标志、真实的系统界面或真实的包装复制品。
- 不要将虚构的概念产品呈现为真实的品牌产品。
- 不要写一个模糊的 “高级 MG 动画” 提示。要包括生成规格、产品设置、整体风格、核心结构、秒拍摄、屏幕文本、画外音、转场和音频指导。
- 不要添加歌词、嘈杂的声音或音乐来压倒画外音。
