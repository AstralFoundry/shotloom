# Windows XP 对话框故事

创建独立的 Windows XP Luna 对话图像和短视频，其中对话变成可读的叙事对象。原始的静态对话功能仍然可用；视频扩展将对话状态、堆叠、进度、失败和完成转换为定时的视觉事件。用户可以提供一个简短的概念、一个静态对话素材、一个参考图像或组合。

## 第 0 步：范围和输入

确定请求是针对一个静态对话框、弹出式驱动视频，还是两者兼而有之。对于视频，请使用下面的强制分段摄入，而不是直接跳转到视频生成。

**对话节奏是强制性的:**每个用户轮次只能推进一个阶段。只询问当前阶段的下一个输入，然后停下来等待。不要列出所有未来的问题，不要提交完整的制作简报，也不要在用户回复当前阶段之前开始后续阶段。在每个阶段完成后，简要说明已完成的内容，只询问下一个所需的输入。

1. **对话资源阶段:**首先设计并生成所需的对话系列：错误、警告、进度、中断和结束状态，符合概念要求。保持它们的色彩和字体一致。生成后，停下来要求输入字符。
2. **角色阶段:**请用户上传角色参考，或确认不需要任何角色。当视频依赖于特定人物或角色时，不要编造角色身份。收到后，停下来询问脚本或故事大纲。
3. **脚本阶段:**请用户上传脚本、对白或场景大纲。准确保留提供的口头和屏幕副本。收到后，停止并仅总结下一个未解决的制作选择。
4. **互动时间线阶段:**将角色行动和故事节奏映射到对白出现、叠加、移动、进度变化、中断、淡出或结束。如有需要，只需询问下一个缺失的持续时间、宽高比、场景参考、语言、字幕或结尾选择。
5. **视频阶段:**只有在对话资源、角色输入、脚本或明确的无脚本决定可用后，才能生成弹出驱动的视频。

如果视频不需要角色或脚本，请要求用户在相关阶段明确确认该决定；不要默默跳过依赖关系。如果缺少持续时间或比例，必须生成视频，只有在工作流程到达生产选择阶段时才能提出这个问题。

精确保留用户提供的每个可见单词。不要在没有语义支持的情况下发明后续系统声明、破坏性行动、法律/安全通知或控制措施。

## 第 1 步：静态对话设计

对于静态素材，将状态分类为处理、完成、警告、错误、确认或输入/结果预览。选择最小的有意义的标题、正文、图标、按钮、层次结构和布局集。默认为一个居中的 4:3 水平对话框，背景完全隔离。不要承诺 Alpha 通道。使用蓝色 Luna 标题栏、经典斜体、可读中文或用户提供的字体，且不要使用桌面、任务栏、硬件或周围环境。

使用默认的可用图像功能。如果用户明确指定了另一个图像模型，请在执行该选择之前检查其功能。如果生成失败，请纠正可能的原因并重试一次；如果仍然失败，请切换到另一个兼容的可用模型。如果用户明确要求使用透明 PNG，请解释生成不保证使用 alpha 通道，并且仅在支持的情况下使用单独的可用提取或后处理步骤。

## 第 2 步：弹出视频剧本

视频扩展是**物理化弹出动作短片**，而不是带 UI 贴纸的对话场景。当要求复古风格时，建议使用明显的早期 DV/2000 年代早期的电视图像，而不是精致的现代电影风格。静态的独立对话只是素材阶段；视频通常应该将角色和对话放置在可信的物理空间或刻意改造的系统空间中。

应用以下视觉规则：

- 将对话视为平面但物理对象，具有深度、透视、前/后遮挡以及与角色或道具的碰撞。
- 将每个主要弹出窗口与一个可见的动作或故事节奏联系起来：影响、打断、回避、未能回应、扔物体、推开或和解。
- 构建一个反馈循环：动作→弹出响应→升级动作→密集弹出响应。
- 仅对可重复使用的对话资源使用干净的隔离背景，而不是在用户提供场景参考后作为默认的最终视频分段。
- 在持续时间允许的情况下，包括至少一个动态升级节拍和一个清晰的系统状态视觉转换。

将视频围绕一个清晰的状态弧线构建，而不是一组不相关的界面镜头。当概念支持时，可以使用以下交互模式：

1. **累积:**重复的错误或警告对话框出现在可见事件之后，占用空间，并创建不断升级的杂乱。
2. 分层和缓解：堆叠的对话框成为一个视觉压力场；在转折点之后，次要对话框会淡出、移到一旁或坍塌，露出一个决定性的对话框。
3. **与动作相关的进度条:**进度条或状态值随屏幕上的动作而变化。变化必须清晰可见，并且具有因果关系；如无故事原因，不要显示任意数字。
4. 系统中断:**当动作是用户概念的一部分时，冻结、崩溃、重启或空白屏幕拍打可能会中断动作，随后会出现干净的返回或终端状态。
5. **结束对话框:**单个完成或结果对话框解决累积状态。其副本必须提供或基于概念，而不是作为未经支持的事实系统结果呈现。
6. **系统载体移动:**当合理时，将设置转换为崩溃屏幕、经典的类桌面系统空间、加载 void 或其他系统状态，然后再返回现实。这是场景转换，而不是通用的桌面重现。
7. **后期状态和反高潮:**结束时会出现黑屏、最终进度完成或系统通知，随后是物理后果或尴尬的静止状态，当它符合笑点时。当角色的物理状态产生最终对比时，分辨率弹出窗口应该会解决系统问题。

当概念需要采取行动时，使用不同的物理空间摄像机语言：交替广角镜头，通过中景、反应特写、插入细节、快速平移或推入，以及系统故障时的短暂定格来揭示弹出密度。避免在整个片段中重复相同的取景或动作。通过前景/背景位置和真实遮挡使景深清晰可辨。保持决定性弹出清晰可辨；保留快速动作用于转场或冲击时刻，而不是每个镜头。

## 第 3 步：时机和声音

将弹出窗口的到达、影响、点击、状态变化、进度变化、冻结、淡出和最终结果映射到节拍时间线上。建立起始状态、动作驱动的升级、转折点和结束状态。将系统声音视为节奏的一部分：弹出窗口点击、错误音、崩溃警报、冻结期间的静音，以及在请求或生成声音时，最后的确认音应与重要动作一起出现。除非用户指定其他语言或声音方向，否则要用自然的台湾普通话进行口语对话，而不要使用播音员的口音或大陆广播的口音。如果提供音乐，要将动作影响和弹出窗口爆发与其结构重音对齐。除非用户要求，否则不要暗示字幕。

## 第 4 步：参考贡献

根据每个提供的图像引用的角色使用。生成或用户提供的全帧图像仍然可以承载场景、人物关系、摄像机和整体外观；人物表可以承载身份连续性；对话框图像可以承载弹出式色彩和状态设计。保持每个引用的贡献不同。如果提供了多个弹出式图像，请将它们用作阶段性状态系列：首先引入错误和警告对话框，仅在故事节点处输入进度或中断状态，并保留完成/结果对话框用于分辨率。除非故事明确要求，否则不要同时显示所有弹出式状态。除非用户明确要求，否则不要传输附带的人物、设置、标志或文字。

## 第 5 步：规划、确认和制作

对于视频，在阶段性录制完成之前，不要生成最终剪辑。只有在对话框资源、角色输入、脚本或明确的无脚本决定可用后，才能提交节拍计划。不要在一条消息中展示整个未来工作流程或收集所有剩余的选择。只确认下一个对制作有实质影响的未决选择，然后等待用户后再继续。首先生成可重复使用的对话框/关键帧资源，然后按时间顺序生成或组装视频。保持重复对话在标题栏比例、字体设计、图标逻辑和按钮放置方面一致，同时允许特定状态的内容。

使用MiniMax-H3 作为默认视频模型。如果用户明确指定了其他模型，请在遵循该选择之前检查其功能。如果生成失败，请修复可能的原因并重试一次；如果仍然失败，请切换到另一个兼容的可用模型，而不是反复重试同一模型。

如果生成的结果失去了对话框的可读性，请在添加装饰细节之前固定尺寸、时序、重叠或镜头运动。如果结果变成了一个通用的桌面场景，请返回提供的场景参考或受限的场景构成；只有在用户提供或批准场景后才锁定场景。如果进度值没有明显响应动作，请简化动作并明确状态转换。保留成功的资源，只重试失败的部分。

## 第 6 步：质量检查

检查以下内容：

- 弹出是一个物理化的叙事主体，而不是一个平面贴纸;
- 场景具有可见的深度、遮挡和清晰的动作 - 弹出式反馈循环;
- 状态弧线是可以理解的，无需依赖于未经支持的阐述;
- 每一个提供的词语都是准确的;
- 累积的对话、行动触发的反应、进度变化、中断、淡出和结束状态都有明确的时序;
- 重复的对白在视觉上保持连贯性，按照故事顺序出现，并与空间保持一致的互动;
- 摄像机不会破坏可读性;
- 结尾解决了既定状态，而不是添加一个不相关的屏幕;
- 音频效果或音乐不意味着存在未经请求的字幕;
- 静态输出使用选定的可用图像功能，并遵循其已检查的约束;
- 结果是按照要求的视频或静态图像，而不是交互式原型。

## 限制

这项技能支持独立的 Windows XP 风格对话图像和物理化弹出驱动的动作短片。它不创建功能性 UI 代码、交互式原型、完整的桌面重现、通用的现代模态系统、不相关的桌面导览、不受支持的系统声明或参考视频的精确副本。静态白色或独立的背景用于对话资源，而不是当用户提供的场景存在时默认的最终视频美学。对于长片、多个独立的最终视频、复杂的多片段编辑，或者需要广泛脚本和镜头审批的工作流程，可以回归到更广泛的制作工作流程。
