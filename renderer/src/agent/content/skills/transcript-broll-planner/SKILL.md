# B-roll 脚本规划器

当用户已经有了文本记录、旁白草稿、数据丰富的叙述或对白脚本，并且需要一个可重复的工作流程来将其转化为 B-roll 规划和生成时，就可以使用这项技能。它是为知识视频、解说员、市场分析和文本导向的编辑而设计的，在这种情况下，模型必须决定哪些内容应该保留为 A-roll，哪些内容需要视觉支持，以及哪些内容应该成为单独的 B-roll 镜头或连续一次拍摄中的一个节拍。

## 输入

要求：
- 一份文字记录、旁白草稿或脚本，其中包含足够的文本，可以根据含义进行细分。

可选：
- 现有素材、截图、标志、UI 截图、产品照片、文档、地图、图表、数据表或其他参考资料。
- 用户约束，如宽高比、每个镜头持续时间、连续拍摄要求、样式方向、屏幕文本语言、目标生成模型，或者输出应该更加直观还是更加抽象。

不要将这项技能用于一次性图像提示、纯字幕输出、简单修剪或不相关的长版本编辑任务。

## 步骤 1:按意义划分文本

阅读抄本并将其分解成语义单元，而不仅仅是基于标点符号的句子。

对于每个单元，决定它是否应该变成：
- A 卷保留
- 证据驱动的支持
- 重复使用现有材料
- 文本包装/动态排版
- 纯视觉 B 卷

规则：
- 尽可能在每个镜头中保持一个核心想法。
- 与其过度剪辑剧本，不如选择更少、更清晰的镜头。
- 如果用户需要一个连续的一次性 B 卷，将所有单元设计成一个连续镜头运动中的节拍，而不是分离的断断续续的镜头。
- 如果一行包含声明、数字、品牌名称、法律文本、引用或任何必须准确的词语，请将其标记为证据或确定性处理，而不是自由形式的视觉创造。
- 如果文字记录太弱，无法自信地分割，请在继续之前询问用户完整的脚本或更清晰的文字记录。

## 第二步：选择最佳模板路线

将每个语义单元与 T01-T21 中最合适的模板族进行匹配。

使用最适合内容类型的模板族：
- 结论、反转、妙语→动态陈述
- 概念、单一隐喻、英雄想法→概念英雄
- 经过验证的数字和排名→数字影响
- 证据、文章、报告和引用→证据摘要或证据桌
- 过程、因果关系、工作流程→关系流或章节顺序
- 比较和对比 → 分裂系统比较
- 系统、组织、机制、分类学→白色立体模型系统、分支分类网络或技术机制解释器
- 产品、零件或组装逻辑→3D 产品组装
- 地理、地图、供应链或全球分布→地理空间情报地图

规则：
- 选择最简单但仍能清晰表达含义的模板。
- 当内容更好地通过证据或干净的覆盖来呈现时，不要强行使用视觉隐喻。
- 如果文本中包含多个想法，这些想法可能会在同一个镜头中相互冲突，那么可以将它们分解成单独的镜头或单独的节拍，形成一个连续的一次性镜头。

## 第三步：确定缺失或所需的材料

检查镜头是否需要用户尚未提供的资源。

常见缺失材料：
- 标志或品牌锁定
- 产品照片
- 应用程序或网站屏幕
- 图表、文件、截图或来源表
- 反复出现的人物或角色的身份引用
- 地图、图表或技术插图
- 必须在屏幕上显示的精确文本

规则：
- 在生成之前提出缺失的必要元素。
- 不要编造事实性内容、品牌声明、引用、法律文本或资料来源引用。
- 如果一个镜头需要准确的措辞，请要求用户或可信来源提供准确的措辞。
- 如果用户指定了屏幕文本语言，请保持所有屏幕文本都使用该语言，同时保持生成提示使用用户要求的提示语言。
- 不要将工作流程绑定到特定的视频模型。提供时请使用用户的明确模型选择；否则，请让主机协调员为批准的计划选择一个可用的模型。

## 第 4 步：制定一个可审核的 B 卷计划

创建一个逐镜头或逐节拍的计划，以便用户可以在任何视频生成之前进行审核。

每个计划项目应包括：
- 拍摄或节拍 ID
- 源代码转录段落
- 家庭模板
- 视觉目的
- 所需素材
- 屏幕文本限制和语言
- 运动和连续性说明
- 是否需要生成视频、证据或确定性工具，而不是自由生成

规则：
- 将每个镜头或节拍集中在一个核心语义单元上。
- 保持屏幕上的文本简短易读。
- 当文本负载变得太重时，可以分割镜头或移除自由文本，并将想法转移到更简洁的视觉分辨率中。
- 当用户要求连续性时，明确描述一个视觉形式如何转换为下一个。
- 如果用户要求更精炼、更直白或更连续的结果，请相应地调整方案，同时保留语义结构。

## 第 5 步：生成前请求批准

计划完成后停止，等待用户批准镜头或请求编辑。

在任何真正的视频生成之前，都需要获得批准。

即使方案看起来很明显，也不要跳过这个关卡。

## 第 6 步：生成批准的镜头

获得批准后，只生成批准的镜头或批准的连续镜头。

规则：
- 尽可能将类似的作品一起批处理。
- 在共享相同主题、产品、数据系统或视觉世界的镜头之间保持连续性。
- 使用评审计划作为拍摄顺序、节拍顺序、运动连续性和素材要求的真实来源。
- 报告任何调用失败、生成失败、未知结果或观察到的内容缺陷，并按照下面的用户决策门进行操作；永远不要自动重试。
- 保持生成的输出有序，以便在后续编辑中进行审核和重复使用。

### 失败和质量审核：用户决策

这些规则适用于每个生成的图像和视频镜头，包括参考图像、关键帧和连续拍摄。它们取代了这个工作流程中的自动重试行为。

1. **调用失败:**如果请求被拒绝，无法提交，或返回调用错误，请报告受影响的镜头/图像、已知错误以及是否存在任何输出。不要编造原因。仅仅超时或响应中断并不能证明生成失败：如果可能，请检查现有任务或返回的素材，否则将结果报告为未知。不要提交重复请求以解决不确定性。
2. **生成失败:**如果生成任务明确失败或完成时没有可用的输出，请单独报告调用失败。保留同一批次中的任何成功输出。
3. **带有内容缺陷的成功输出:**检查可用结果并揭示具体观察到的缺陷，例如文本错误、主题漂移、连续性中断、产物或与批准计划的不匹配。保持输出成功生成并等待用户质量审核；缺陷不是执行失败。显示素材进行审核。如果检查不完整，请说明限制，而不是宣布质量通过或失败。
4. **停止决策:**报告失败、未知结果或内容缺陷后，暂停新生成和依赖性工作，并询问用户该怎么办。已经运行的批处理任务不需要丢弃；保留并报告其结果。对于失败，提供重试、修改计划、跳过或停止。对于有缺陷但成功的输出，提供接受原样，指定编辑、重新生成、跳过或停止。如果有用，建议选择，但不要代表用户做出选择。
5. **无自动恢复:**在报告问题后，不得自动重试、再生、修复、更改模型或参数或重写提示。最初的计划批准、拒绝结果或一般性继续请求并非完全允许重试或修复。获得明确的决定，确定受影响的素材和预期行动；仅在范围模糊时进行澄清。
6. **范围授权后续:**一旦明确授权，仅对命名的失败、缺失或用户选择的素材执行选定的操作。重用所有其他成功的输出，保持原始输出可用于比较，并且默认情况下永远不要重新运行整个计划。每次授权只包含一次尝试，而不是重试循环。如果该尝试失败或出现新的缺陷，请再次报告并等待新的决定。

问题报告应包括镜头/图像标识符、结果类别（调用失败/生成失败/未知/产生内容缺陷）、可用素材、观察到的错误或缺陷、受影响的依赖关系以及请求的决策。不应声称未经验证的成本、退款、完成或质量结果。

## 第 7 步：交付计划和素材

返回最终的 B-roll 计划、生成的照片和图像，以及用户可以立即查看的任何缺失材料笔记。单独列出未解决的故障、未知的结果和已发现的内容缺陷，包括用户的决定和任何待决选择。不要将未完成或未被接受的作品呈现为完全完成或批准。

这项技能最适合转录驱动的 B-roll 规划和审批制视频生成。它不适用于纯粹的字幕翻译、简单的修剪、长篇剧本写作或无关的品牌推广工作流程。
