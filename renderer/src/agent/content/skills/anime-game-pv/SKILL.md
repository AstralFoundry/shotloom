# 动画漫画/游戏 PV

提供一个统一、可观看的动画漫画或游戏 PV——而不仅仅是分析、分镜或提示。这项技能在一个连续的过程中完成物质判断、视觉融合、分镜制作、提示编译、执行约定和最终验收，无需分割独立的执行计划；每个视频生成都会产生一个完整的候选视频。提交确认的视频提示，逐字逐句；后续步骤不得重写。

## 生产模型

| 实体 | 定义 |
| --- | --- |
| `Candidate Ref Capsule` | 来自媒体分析的候选素材贡献；它只描述可能的角色，并不拥有最终风格或执行权限。 |
| `Style Source` | 用户在风格权限门确认的来源：原始材料、书面方向、独立风格参考或本技能提出的新方向。它决定了后续的视觉制作。 |
| `Style Authority` | 实际输入视频提示的单一样式权限；其类型可能只是`existing_asset`或`generated_asset`。用户的书面指示或内部视觉系统可能会变成`style_source`，但在需要生成视觉权限图像的路径中，它们可能不会直接模仿最终的`style_authority`。 |
| `Palette Authority` | 颜色约定进入视觉权威图像和视频提示。内部默认视觉路径包括黑白结构、一种高纯度主题颜色，以及可选的最小重音；其他风格按用户或权威风格来源的调色盘锁定，无需强制单色。 |
| `Visual Artifact Type` | 新生成的视觉权威图像的实际图像形式。具体类型仅适用于`style_authority_kind=generated_asset`;现有材料的直接重用必须是`not_applicable`。 |
| `Render Ref Capsule` | 材料约定实际上进入了视频生成，具有非空的`roles`、正向贡献边界和真实的路径。 |
| `Panel` | 语义分镜中一个时间点或状态的制作单元，用于确认构图、动作进度和连续性。 |
| `Logical Shot` | 主时间线中包含一个或多个面板的连续叙事跨度；它是一个提示性章节，而不是独立的视频素材。 |
| `Master Timeline` | 包含所有逻辑镜头的单一完整生成计划。 |
| `Storyboard Preview` | 一个可选的九格结构，源于当前的语义分镜。当它出现时，可以帮助提示构图、动作阶段和镜头切换；它既不是人物/风格权威，也不是视频参考插槽。 |
| `Storyboard Package` | 一个完整可审阅的分镜版本:`storyboard_review.md`、所有面板、逻辑镜头、主时间线，以及用户选择查看时的分镜预览版。 |
| `Storyboard Approval` | 用户对当前分镜包的批准收据通过一张真实的确认卡；它必须绑定`storyboard_revision`，如果存在九格，还必须加上`preview_revision`。这种批准还授权在飞行前通过后立即编译和直接生成。 |
| `Render Contract` | 完整一代的可执行约定；草案首先锁定功能和计划，然后锁定身份、单一风格和调色板权限、实际参考槽、执行设置、及时预算和最终文件数量。 |
| `Render Attempt` | 一个已确认的渲染约定，一个飞行前通过的完整提示，一个视频执行批处理，以及一个完整的候选视频。 |
| `Final Video` | 通过检查并被选中的渲染尝试；它会替换之前的候选者，而不是与之匹配。 |

制作拓扑是固定的：无声摄入→制作路线和身份确认→风格权限门→色彩方向和参考处理→视觉权限决定→渲染约定草案→必要的视觉权限图像和单个`style_authority`→锁定渲染约定→面板→逻辑镜头→主时间线→可选的九格→完整的分镜包确认→`final_video_prompt`编译和预览→一次完整的渲染尝试。`production_route`记录用户的选择，永远不会重写；是否必须生成视觉权限图像，将通过`requires_visual_authority_asset`独立派生。每次渲染尝试始终会产生一个完整的候选视频；多部独立的最终影片、超过 15 秒的时长或跨视频连续性都超出了本技能的传递范围。

## 互动约定

制作前先建立 `intake_state`：从用户原话、真实附件和画布素材中提取交付路线、身份来源、风格候选与权威、视觉策略、色彩约定、参考处理、时长、画幅、音频计划和各阶段审批状态。用户已给出的身份、规格、音频和材料直接继承，不重复询问；风格方向必须显式确认，不能从文本或附件静默推定。

固定顺序：无声摄入 → 素材与候选参考 → 风格权限门 → 色彩约定 → 视觉路径 → 剩余规格 → 视觉确认 → 锁定 `style_authority` 与渲染约定 → 分镜包确认 → 编译预检 → 生成。任何阶段都不得提前提升候选来源，也不得跳过上游产物的批准；上游变更按依赖关系使下游审批失效。

需要用户选择、确认或授权时一律使用确认卡；确认卡取消且没有有效结果时停在当前门。

完整字段、失效规则、无声输入判定、路线/色彩/视觉授权细节见 `references/interaction-conventions.md`。

## 1.确定适用的意图和交付范围

“漫画 PV、漫画 PV、动画故事 PV、角色/组合 PV” 是这个技能的明确积极信号。当主体仍然是 2D 漫画/动画角色或故事时，诸如 “电影 PV、预告片、预告片” 等通用术语的适用性不会改变。

构建概要：无论目标是人物/整体故事揭秘、觉醒、战斗预告、世界观展示还是抽奖/事件推广；创纪录的持续时间、纵横比、确切的标题文本、支持资源和`production_route / identity_source / has_valid_image_asset / style_candidates / style_source / style_authority / style_authority_kind / visual_policy / default_editorial_active / dominant_theme_color / accent_color / accent_policy / character_palette_policy / palette_authority / saturation_policy / reference_processing / requires_visual_authority_asset / visual_artifact_type / visual_authority_revision / visual_authority_status / narrative_focus / audio_plan / audio_drive`。所有领域都是根据互动契约推断或确认的——绝不会重新组合成一个综合的多选项形式。

这些意图超出了本技能的能力范围；请向用户解释相关边界并停止使用本技能：

- 以标题、演员阵容、片头标题、片尾字幕或标题效果为主题。
- 将静止图像、歌词文本或动态类型作为主题。
- 音乐、说唱、时尚表演或 MV 作为主要叙事。
- 通用运动设计 MG。
- 以品牌技术蒙太奇或系统视觉效果为主题。
- 参考视频的逐帧解构和再创作。
- 现场动作广告、3D 动画、长篇叙事、多部独立电影或跨视频连续性。

在原始动画 PV 中，仅用于节奏、摄像机、过渡或媒介的参考视频将保留在这项技能中，不会继承其任何角色、世界、品牌或文本。

## 2.确定素材、身份、风格来源和色彩策略

1. 通过媒体分析分析相关图像、视频和音频，首先为每个项目建立候选参考胶囊:`{ id, candidate_roles, contributes, take }`。`candidate_roles`是`subject | scene | style | layout | action | audio`的集合；分析结果永远不会取代风格权限门。
2. 站立艺术、角色图像和转折默认只显示高分量的身份参考：锁定面部、头发、体型、衣橱、配饰、武器、标记、人数和关系；最终视频不需要显示所有视角，而且它们自身的线条、着色或构图不会自动授予`style`权威。
3. 场景候选者只能锁定空间和世界；风格候选者只能贡献媒介、材料、色彩和动作语言；布局候选者只能贡献层次、网格、遮挡、切片和锁定逻辑；动作候选者只能贡献动作 - 摄像机关系。只有在风格权限门口明确选定后，材料才能从候选者的贡献转化为最终的`style`角色。
4. 风格权威门仅建立`style_source`、`visual_policy`和`default_editorial_active`，从不提前确定最终素材角色或关键视觉形式。经过调色板和处理后，通过`references/visual-inputs.md`中的决策矩阵统一推导`style_authority_kind / requires_visual_authority_asset / visual_artifact_type`;当必须生成视觉权威图像时，未转换的角色素材和新的构件可能无法共同作为多个视频风格权威。

确认`style_source`后，按路径构建颜色权限：

1. 使用`default_editorial_active=true`时，严格按照`dominant_theme_color → accent_color|null → accent_policy → palette_authority`完成门。重音不是第二重要的；默认情况下不推荐重音，只有在叙事需要单一语义差异时才启用重音。UI 只显示实际的颜色方向和功能——而不显示内部系统名称。
2. `faithful`、用户书面说明或独立风格引用按照确认的来源锁定调色板；仅在用户明确的重新配色请求下进行覆盖——绝不强制使用黑白单主题。
3. 角色原色和电影的编辑调色板是分开管理的。`character_palette_policy`遵循处理答案；额外的角色色彩仅限于识别区域，绝不会扩展到背景、MG、UI 或转场。

内部默认路径的具体视觉语法、颜色预算、字符调色板处理和产物验收以`references/visual-inputs.md`为唯一真实来源；该文件只决定何时输入该路径以及必须完成哪些确认，而不重复视觉细节。

## 3. 锁定渲染约定和视觉参考

首先检查当前能力总结，优先选择可用的默认视频路径。选择模型路径后，记录一份人类可读的渲染约定草案，其中包括审批状态、身份和风格权威、调色板、参考角色、持续时间、宽高比、音频、提示预算和最终文件数量。不要将私有实现字段复制到文档中。

- 草稿锁定了`style_source`、`visual_policy`、`default_editorial_active`、`reference_processing`、`style_authority_kind`、`requires_visual_authority_asset`、`visual_artifact_type`和模型功能。`generated_asset`路径必须标记`style_authority=pending / visual_authority_status=pending`，只有在用户确认修订后才能写入实际素材和批准的设置;`existing_asset`路径直接使用`visual_authority_status=not_applicable / visual_artifact_type=not_applicable`写入确认的材料。锁定的 Render Contract 不允许任何待处理字段。
- 内部默认路径必须锁定`dominant_theme_color`、无效`accent_color`、`accent_policy`、`character_palette_policy`、`palette_authority`和`saturation_policy`;选择无重音使用显式`accent_color=none / accent_policy=none`，而不是挂起。其他样式标记不适用的字段`not_applicable`并锁定其源面板。所有适用的字段在可视权限图像和最终提示词中保持不变，但内部字段名称永远不会出现在用户可见的问题、摘要或提示标题中。
- 模型设置必须保持在当前能力总结公布的范围内；常见的交付约束与模型特定的设置保持独立。
- 草案的`reference_slots`仅记录计划的素材类型、顺序、计数、持续时间限制、现有身份素材路径和待定锚点；最终`roles`和实际路径在确认关键视觉/锚点后进入 Render Ref Capsules。在及时编译之前，所有槽位必须完全锁定；候选角色、未确认的风格和没有合法槽位的素材可能不会伪装成参与者。
- `prompt_budget`通过统一优先级来解决：当前能力总结→`references/prompt-rules.md`中的模型指导→那里提到的保守回退。当两个来源都没有暴露提前限制时，在编译之前停止并请求能力证据；永远不要仅仅在失败的生成之后才猜测预算或进行修剪。
- `final_output_count`在本技能中固定为`1`;内部面板和逻辑镜头永远不会增加文件数量。
- 渲染约定仅锁定执行条件，永远不会替代分镜审批。即使锁定，`final_video_prompt`在当前分镜包未下载或未经审批时也可能无法编译。

阅读`references/visual-inputs.md`并根据单个决策矩阵，决定是重用现有的授权素材还是生成某种类型的视觉授权图像，然后在草稿允许的模式和槽中选择实际的视频引用；绝不要悄悄地丢弃材料以强制使用某种模式。`generated_asset`路径必须在填充单个`style_authority`、Render Reference Capsules、实际路径和引用槽之前完成视觉授权确认;`existing_asset`路径不能伪造生成的`visual_artifact_type`。只有锁定的 Render Contract 才能进入提前编译；更改样式源、视觉形式、调色板、处理、模型、模式、声音、绑定或参数将根据统一的无效规则返回到匹配阶段。

如果没有有效的图像资源可以直接输入视频引用，就必须生成一个与当前风格路径一致的视觉权威图像——不能直接生成无图像的图像。使用`requires_visual_authority_asset=false`时，只能重用已确认可用于生产的素材，并保留单一的`style_authority`。
- 只有当用户明确要求精确的开始、精确的结束或指定的时间帧时，才应被动验证和使用模型支持的时间锚定模式；永远不要主动介绍、推荐或询问第一帧、最后一帧、第一帧和最后一帧或关键帧锁定，也不要引导用户从预览中剪切面板作为视频参考。

当需要视觉权威图像时，首先查询图像功能，然后根据`references/visual-inputs.md`和当前`visual_artifact_type`中的共享视觉权威约定编译图像提示词，使用图像生成实现权威身份贡献、`style_source`、适用的调色板字段、`reference_processing`和图像形式。图像提示词必须分离必须保留的身份、可能适用的表达方式和禁止继承的载体信息；绝不要使用 “优化原件”、“保留原始构图” 或路径无关的 “生成促销海报/KV” 短语。生成或覆盖素材将创建新的`visual_authority_revision`并设置`visual_authority_status=pending`。

生成后，请通过媒体分析检查当前的`visual_artifact_type`。所有路径都必须保持身份边界，并去除非遗传性载体污染；定向和融合风格的路径必须符合所选风格；重新设计必须保持在允许的变化范围内；内部默认路径必须通过单主题预算、重音预算、纯白/近白皮肤、硬黑色阴影、扁平色块、低信息背景和动画截图感觉检查，同时既不能仅仅是原作的重新着色，也不能是精心制作的宣传海报、回放或最终分镜。失败的路径永远不会升级到`style_authority`;在相同的视觉阶段修复匹配约定并重新生成。

通过后，将其放在画布上，并通过确认卡提交:“继续使用当前视觉参考/调整风格表达/调整调色板/调整参考处理/调整角色一致性。” 确认当前修订集后，将 `visual_authority_status=approved`；调整选项返回到匹配的制作层，不要将每个问题都压缩成海报重做。不要为每个逻辑镜头生成单独的视觉参考。

确认关键视觉效果和锚点后，将所有实际进入视频生成的素材标准化为 Render Ref Capsules:`{ id, roles, contributes, take }`。`roles`是`subject | scene | style | layout | action | audio`的非空子集。在`faithful`下，如果没有新的关键视觉效果，确认的原始角色素材可能会使用`[subject, style]`;在新的关键视觉效果下，原始角色素材只保留`[subject]`，而确认的关键视觉效果使用`[style]`;已经被关键视觉效果吸收的独立风格图像不再作为第二风格权威传递。其他素材携带其确认的场景、布局、动作或音频角色，只保留一个`style_authority`。只有在这些转换和实际路径完成后，Render Contract 才能被锁定。

## 4. 制作面板、逻辑镜头和主时间线

默认情况下，先生成语义分镜——无需九格。每个面板在`storyboard_review.md`中记录其时间点或跨度、帧、主题和动作状态、前/中/背景、摄像机状态、文本/图像事件、过渡基础、声音提示和继承自前一个面板的连续性。面板是中间制作单元，从不独立的视频素材，也从不直接输入视频参考。

将完成的面板整合到逻辑镜头中。每个记录：时间范围、叙事任务、包含面板、开始状态、主要动作、结束状态、摄像机轴、光线、环境、转场界面、文本状态和声音范围。相邻的面板可以共同描述一个逻辑镜头的持续开发。

将所有逻辑镜头安排在一个主时间线中。叙事可以使用 “钩子→主题/空间建立→动作或情感发展→高潮→稳定锁定” 的弧线，而无需预设类型模板；结构必须来自用户的目标和素材。

按照固定顺序完成分镜包：

1. 创建或覆盖单个`storyboard_review.md`，包括在画布上书写、撰写完整的概要、素材贡献、`style_source → style_authority`、`visual_artifact_type`、调色板权限、饱和度策略、参考处理、音色方案、所有面板、逻辑镜头分组，以及一个无间隙的主时间线。
2. 确认完整的`storyboard_review.md`在画布上可见；永远不要让`final_video_prompt.md`作为分镜脚本文档。
3. 根据当前分镜文本节点及其语义创建一个新的`storyboard_revision`，设置`storyboard_status=pending`。在任何九格网格存在之前记录`preview_revision=none`。
4. 呼叫分镜确认卡，提供 “确认分镜并生成/查看九格预览/调整叙事和节奏/调整角色和动作/调整视觉和声音” 的服务。分镜审批将约束当前`storyboard_revision`、已锁定的 Render Contract 和`preview_revision`（如果存在）;如有调整请求，请覆盖产物，形成新的修订，然后再次等待。

只有当用户选择 “查看九格预览” 时，才能从当前语义分镜中派生出一个九格，将节点命名为`《project name》nine-grid storyboard preview`，并直白地说明:“九格确认镜头顺序、动作节拍和构图方向；确认后，其可执行的构图和动作信息将转换为视频提示，但九格图像本身不会作为视频参考。角色和风格通过确认的视觉权限保持一致，运动和镜头转场遵循主时间线。” 预览完成后，记录一个新的`preview_revision`，保留`storyboard_status=pending`，并立即返回相同的分镜确认确认卡。当用户想要更改预览时，首先修改匹配的面板、逻辑镜头或主时间线，形成一个新的`storyboard_revision`，然后从新的语义中重新派生预览；永远不要只编辑预览图像。重新生成九个网格会产生一个新的`preview_revision`，使旧的分镜审批无效并设置`prompt_status=pending`。

Storyboard 确认卡结束这个阶段。如果没有与当前修订相关的有效确认，永远不要输入提示编译，永远不要创建或覆盖`final_video_prompt.md`，也永远不要将 “storyboard 完成” 或 “下一步编译提示” 等回复视为隐含批准。

## 5. 从批准的 Storyboard 包中编译和预试

在输入之前，请验证:`storyboard_status=approved`;批准的`storyboard_revision`与画布语义匹配；使用九网格时，其绑定的`preview_revision`与画布预览匹配；渲染约定处于锁定状态。任何失败都会返回到第 4 阶段，而不会创建提示。然后阅读`references/prompt-rules.md`和`references/audio-direction.md`，从批准的分镜包中编译单个`final_video_prompt`，从一开始就遵循渲染约定的`prompt_budget`——千万不要先编写无绑定版本，然后在失败后进行压缩。提示按顺序包含：

1. 持续时间、宽高比、模式和单个最终视频目标;
2. 材料参考和每个参考胶囊的正向贡献边界;
3. 人物、场景、单一风格权限、视觉效果形式、调色板权限、饱和度策略、参考处理和文本连续性锁定;
4. 使用九格网格时，其构图、动作阶段、取景和拍摄切换——与语义分镜一致——转换为 “分镜序列约束”;没有图像参考路径，没有图像插槽;
5. 每个逻辑镜头在主时间线中的开始状态、动作、结束状态和向下一个镜头的切换;
6. 用户词语、图像处理、原声或确认音频的真实参考关系;
7. 最终锁定和稳定保持。

面板永远不会一对一地映射到提示章节，也不会按网格逐一复制；逻辑镜头是提示的时间章节。九个网格只是补充构图和动作阶段，这些阶段与批准的语义一致——永远不要添加、删除或重写镜头任务；如果发生冲突，就停止编译，回到分镜阶段进行调和。动作必须写成可观察的摄像机路径、主体动作、图层变化、物理转换和声音事件——永远不要用 “电影般的、令人惊叹的、平滑的” 来代替随时间推移而发生的变化。

`final_video_prompt`的文档标题、部分标题、逻辑镜头叙事名称和主体都使用运行时注入的`working_language`;模型 ID、模式名称、材料标签、文件路径和用户的确切文本都保持逐字逐句。提示词必须保持`references/prompt-rules.md`定义的语义章节顺序和逻辑镜头部分，绝不能压缩成一个段落或聊天摘要。

完整的可执行编译按以下顺序进行：

1. 编译候选提示词，并通过写入画布创建或覆盖单个`final_video_prompt.md`文档节点；主体必须与要分发的提示词字符相同。
2. 计算最终的提示词字符，并将它们与渲染协议中的`prompt_budget`进行精确比较。
3. 当超出预算时，应用`references/prompt-rules.md`中的确定性收敛顺序——删除重复的身份、重复的风格、重复的负片和无信息的镜头措辞——覆盖同一文档并重述最终提示；绝不要牺牲时间线覆盖范围、动作因果关系、素材绑定或声音事件。
4. 在同一提示词和渲染约定上运行统一预试：风格权限门、单一风格和调色盘权限、提示词长度、模型参数白名单、模型和模式、最终素材角色、插槽/计数/持续时间、实际路径、音频方案、持续时间、宽高比、分辨率、最终文件计数和未分辨的占位符。
5. 任何失败都将返回到匹配约定、分镜或编译阶段，而不需要创建渲染尝试。在完全通过后，设置`prompt_status=approved`并直接进行调度。

在提前编译和调度之后，如果用户主动请求更改，首先要判断已批准的分镜语义是否发生变化：镜头、时间范围、叙述职责、动作、过渡、构图、声音事件或结束状态是否回到第 4 阶段，形成新的`storyboard_revision`，并重新传递分镜门；保留语义的措辞压缩、法律参数、模型或参考槽修复更新 Render Contract 或相同的`final_video_prompt.md`，然后重新预览并继续调度。

## 6.创建、检查和修复 Render Attempts

只有当`storyboard_status=approved`、`prompt_status=approved`和分镜审批仍然绑定当前作品时，才能将已确认的渲染约定和`final_video_prompt.md`作为不可变的执行简报交给一个视频生成。在生成之前，请验证简报是否仍然满足约定，然后提交具有已确认素材顺序和设置的字符相同的提示。之后的步骤不得总结、翻译、重写、压缩、添加设置、切换模型、更改绑定、扁平化 Markdown 结构或将逻辑镜头分割成单独的视频任务。

故障会在制作阶段反馈回来：

1. 提前发现非法参数、长度、模式、素材或路径：返回 Render Contract / prompt 编译；不创建 Render Attempt，也不启动生成。
2. 需要更改样式权限、产物形式、调色板、处理或饱和度的修复：返回匹配的样式权限门、调色板或处理确认，根据需要重新生成视觉权限图像，然后更新主时间线、渲染约定、提示、预飞行和受影响的门。
3. 修改镜头、时间线、动作、过渡、构图、声音事件或结尾：返回分镜包，形成新的修订版，重新通过分镜门，然后重新编译；保留语义的措辞、参数、模型或槽修改更新约定和相同的提示文档，重新预览，并继续执行。
4. 生成成功，但角色、风格、动作、节奏、声音或过渡质量失败，无需更改已确认的权限：输入以下全面再生流程。

无需通过无声丢弃参数、临时提示压缩、材料替换或模型切换来处理故障，也不需要在重新确认时进行自动重试。

生成后，请通过媒体分析进行检查：角色身份、剪影、与已确认的`style_authority`、`palette_authority`和`saturation_policy`的一致性、内部路径的主题/重音预算和角色调色板策略、动作可读性、文本、镜头切换、过渡、节奏、声音关系、最终持续时间和手工制品。

默认修复策略是全件再生：

1. 在主时间线中定位故障。
2. 修改匹配的面板、逻辑镜头、连续性锁定或时间线说明，覆盖分镜包。
3. 形成一个新的`storyboard_revision`并重新传递分镜门。
4. 从批准的分镜脚本重新编译完整的`final_video_prompt`;当执行条件发生变化时更新渲染约定。
5. 统一的预飞行和调度在通过后立即重新运行。
6. 创建一个新的完整 Render Attempt，重新检查完整的视频，并用通过的视频替换旧的候选视频。

永远不要生成部分视频补丁，永远不要将修复后的镜头拼接到旧视频中，永远不要逐字重新提交失败的通话，也永远不要悄悄切换模型或丢弃参考材料。

## 7. 完成并提交

验证持续时间、宽高比、最终文件计数、字符连续性、单一风格权限、产物形式、调色板权限和饱和度策略、内部路径的颜色预算、文本准确性、动作完整性、逻辑镜头切换、声源和最终保持。除非明确要求，否则不要生成字幕。

导出一个完整的最终视频。九格预览、视觉权威图像、标题卡或最终提示只能根据请求作为辅助资源提供。最终回复提供胶片路径或画布伪影、持续时间/宽高比、参考贡献摘要、声源和一个可行的下一轮改进建议。
