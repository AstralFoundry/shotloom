# Shotloom 技能创建

把用户需要反复使用的方法写成产品 Skill。这里创建的是 Shotloom 技能库中的用户技能，通过官方 Harness 发现和加载，不是给本机 Codex 安装技能或修改 Harness 插件。

## 结合实际工作台

- 用 `inspect_skills` 查看已有技能，修改前传 `skillId` 读取完整正文与 `updatedAt`。避免重复创建；内置技能要另存新 ID。
- 从用户目标和已验证的制作过程提炼适用场景、输入、输出、领域判断和失败恢复。明确的信息直接使用，只有显著影响结果的歧义才用官方提问工具澄清。
- 根据真实工具目录选择角色：`canvas-primary` 操作画布、素材和生成任务；`text-primary` 只编辑绑定文本草稿；`editor-primary` 操作绑定剪辑时间线。不要把只能在某工作台执行的流程分给不具备工具的角色。
- 画布流程根据需要读取 `project_snapshot`、`inspect_assets`、`inspect_model_catalog` 和节点详情，使用真实模型参数及节点引用。角色、场景、分镜、道具节点显式填写对应 artifactType（character、scene、storyboard、prop）；视频仍使用实际技术类型。
- 文本与剪辑流程使用各自当前真实暴露的工具。不要凭想象编造工具、模型 ID、文件路径、任务回执，或在技能里固化用户密钥、私有媒体字节及临时 Session ID。

## 编写正文

`description` 简明说明做什么、何时适用。`instructions` 是 Markdown 正文，保存工具会为官方 bundle 生成 name/description frontmatter，不要在正文里重复粘贴 frontmatter。

只保留能改善领域判断的信息。模型自行理解语义、选择工作流、拆分任务与评审结果；不要把某个示例变成固定镜头数量、关键词路由或强制追问。需要规划、目标续行、审批、提问时使用官方 Plan、Goal、Approval、User Questions，不编写另一套调度器。

技能不能扩大权限：节点执行受用户设置约束，付费、删除、覆盖及 Bash 使用现有工具和官方审批。完成声明依赖真实节点、任务、文件或成功回执；失败时读取事实并修复，结果未知时不得盲目重试付费操作。

当前用户技能保存接口只支持正文和产品元数据，不支持上传 references/scripts/assets bundle。把必要说明写成自包含正文，不链接不存在的附属文件。已安装内置技能的资料仍由官方 `read_skill_reference` 按授权读取。

## 保存与验证

用 `save_skill` 提交稳定的小写连字符 ID、名称、用途说明、正文和明确的 `agentIds`。用户技能在全局技能库持久保存，对以后符合角色分配的会话可用，不是仅当前工程的临时提示词；不要把项目独有数据写成全局规则。更新时提交刚读取的 `expectedUpdatedAt`，冲突后重读并合并，不覆盖用户后来修改。

保存走官方审批；拒绝时保留草稿，不改用 Bash 绕过。保存成功后用 `inspect_skills` 回读核验正文与分配。Tool Bridge 的 activation 回执说明当前会话是否刷新成功；分配给其他角色时在对应工作台重新打开会话加载。禁用状态不会被保存动作自动改成启用。

用官方 `skill` 加载已启用且属于当前角色的新技能，确认目录可发现、正文可读取。使用真实、低成本的任务验证关键步骤；付费生成只在用户已授权时执行。只做了保存或加载验证时如实说明，不声称已经验证完整生成质量。依据真实反馈迭代技能，避免积累无关规则。
