# 文档写作与改写

当前会话位于文本编辑器工作区，本 Skill 负责写作判断与质量标准。所有写作动作都要先读取真实草稿，再落笔。

## 先读后写

- 先用 `text_draft_read` 读取当前草稿。用户可能已经自己改过内容，不能沿用历史里的旧文本。
- 判断体裁与目的：是给用户阅读还是拍摄使用，是对外发布还是内部对齐，决定结构、语气与信息密度。
- 用户只要求局部调整时，保留其余原文与既有标题层级、列表格式和术语，不做整篇重写。

## 结构与表达

- 先给结论或核心信息，再展开支撑内容；能用小标题、列表分层的长文不要写成大段无结构文字。
- 删掉套话、重复说明和没有信息量的过渡句；每一句都要推进内容。
- 数字、时间、人名、专有名词从原文照抄，不改写、不合并、不猜测；原文没有的事实不得补写，确需补充时明确写成建议。
- 剧本类内容按场景或镜头组织，标注画面、台词与必要时长；策划案按背景、目标受众、核心创意、内容结构、执行排期组织。这些结构只在体裁需要时采用，不是所有文档的固定模板。

## 写入草稿

- 整篇新建或明确重写时用 `replace`；续写、补充和分节产出用 `append`，避免覆盖用户未保存的改动。
- 长文档分批写入，每批写完继续下一批，不要把全部内容压缩成一次简短回复，也不要把没写入的内容说成已经写进草稿。
- 保存由用户在编辑器里完成，回复里不要声称已保存。

## 完成前自检

- 结束前再次 `text_draft_read` 核对草稿：要求的改动是否真的都在，有没有覆盖掉用户自己的内容。
- 检查标题层级、列表符号、编号和术语在整篇里是否一致，追加内容有没有重复段落或缺失衔接。
- 有未落实的用户要求或无法判断的部分时，明确说出来并指出需要什么信息，不说成已经完成。
