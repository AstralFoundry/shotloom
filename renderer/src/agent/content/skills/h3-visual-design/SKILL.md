# H3 视觉 Shotloom

主文件只决定视觉技术，并不包含具体的样式规范；一旦选择了一条路线，就可以根据需要阅读相应的参考素材——该参考素材包含设置、提示、生成和交付规则。

## 1. 触发条件

当请求的结果是一个集中的运动设计处理时，输入这个技能：

| 范围内意图 |
| --- |
| 直接生成动态排版或包装作品，或者添加动态类型、标题、卡片、图形、说明、标志处理、材质纹理或 AE 风格的布局到人物、产品、标志、场景、有声视频或原始素材中。结果可能包括准确的用户文本、精心策划的文本、对白说明、跟踪文本以及主体与周围空间之间设计的过渡。 |
| 产生 TD/TouchDesigner/CV 跟踪视觉效果，使受试者的感知数据可视化，包括跟踪帧、角括号、拓扑线、点云、数字 ID、扫描网格、部分负片、颜色反转、调试叠加或 AI 感知视图。结果应该可视化地跟随人、物体或场景，而不是表现为一般的抽象效果。 |
| 通过可见的接触和互动，将真实的生活空间或现场动作表演与 2D 手绘、涂鸦、蜡笔或粉笔动画融合在一起，例如绘制的物体进入房间、包围一个人、对运动做出反应，或在物理状态和绘制状态之间变形。 |

根据用户想要交付的核心结果来判断。如果请求集中在其他类型的最终可交付成果上，请解释它超出了这个技能的范围，并停止这个技能；不要指定其他技能或工作流程。永远不要基于单个关键字扩展这个技能的范围。

## 2. 路线选择

| 主导意图 | 路线 | 所需参考资料 |
| --- | --- | --- |
| 将动态类型、标题、卡片、图形、说明或 AE 风格包装添加到个人、产品、标志、场景、有声视频或原始素材中 | `typography-packaging` | [typography-packaging.md](references/typography-packaging.md) |
| 生成 TD/TouchDesigner/CV 调试视觉效果、跟踪帧、拓扑线、数字 ID、部分底片或 “AI 所见的世界” | `td-cv-tracking` | [td-cv-tracking.md](references/td-cv-tracking.md) |
| 制作将真实生活空间与 2D 手绘、涂鸦、蜡笔或粉笔动画融合的视频 | `handdrawn-live-action` | [handdrawn-live-action.md](references/handdrawn-live-action.md) |

当 TD/CV 或手绘融合意图明确显示时，首先输入该路径；所有其他动态类型、标志、口头语言和材料包装都进入`typography-packaging`。永远不要从 “酷”、“效果” 或 “视觉氛围” 等微弱信号中猜测路径；当关键信息缺失时，请询问用户一次他们想要哪种技术。

默认情况下，一个任务只读取一条路由。当用户明确要求结合两种技术时，首先决定主要路由，然后只读取一个额外的相关参考；永远不要预加载所有路由，也不要将三个规则集合并到一个提示词中。

对于`typography-packaging`，只需要询问缺失的输出宽高比和持续时间。使用明确的用户风格和文本选择；否则，根据现有事实组合并直接呈现，无需额外的确认环节。对于内部默认值，请按照路由参考。

## 3. 共享执行约束

1. 在这项技能中，将工作作为一个连续的流程来完成；之后的任何步骤都不能重新设计已确定的方向。
2. 只阅读所选路线明确要求的参考素材；路线参考是具体问题、提示结构、生成方法和完成标准的真实来源。
3. 仅使用实际存在的附件、现有材料和用户事实；永远不要虚构素材路径、品牌、文本、个人身份或参考关系。
4. 保留用户的明确模型、持续时间、宽高比、主题、副本和音频要求；只询问阻塞所选路由的缺失信息。
5. 在路由生成最终提示词后，向用户显示的提示词和实际用于 H3 生成的提示词必须字符相同；后续步骤不得对其进行总结、翻译或重写。
6. 路由的硬规则优先于这个主文件的通用规则；在路由通过其自身的完成检查之前，不要提交。
