# 短剧剧本写作

用当前打开的文本草稿作为工作对象。先 `text_draft_read`，按用户要求完成企划、人物、分集、正文或局部修订；写入使用 `text_draft_write`，结束前再读草稿核对实际内容。草稿写入不等于保存。用户只要其中一项时，直接产出该项，不强制补齐整套流水线。

## 写作判断

- 先确定用户给定的题材、人物、世界规则、平台格式、集数和时长；已给信息优先，缺口可提出明确创作假设。只有缺口会造成显著不同的成品时才用 `ask_user_question`。
- 把每一场写成有因果的行动：人物想得到什么、谁或什么阻拦、采取什么做法、出现什么新信息或代价、局面如何改变。钩子和反转要从既有动机与证据生长，不能靠无铺垫的巧合或角色突然变笨。
- 正文写可拍到、可听到的内容。场景标明人物、地点和时间；动作呈现可观察的变化；台词符合人物关系与说话习惯，避免用对话复述双方已知背景。旁白和内心独白只在用户要的形式或故事确有需要时使用。
- 开场尽快给观众一个可理解的悬念、关系变化或冲突；每集有可感知的进展，结尾按作品需要选择悬念、情绪回响或阶段性解决。不要为套公式强行断章。
- 集数、字数、场景数、所谓“爆款”指标都随用户的目标平台和交付规格决定，不能把参考仓库的红果示例当成 Shotloom 的默认硬规则。

## 按任务读取方法

- 立项、人物与分集规划：读取 `references/series-design.md`。
- 写单集或连续多集正文：读取 `references/episode-script.md`；多集时再读 `references/series-design.md` 的连续性部分。
- 精修现有剧本：读取 `references/script-review.md`，保留用户未要求改动的设定与段落。

上述参考文件通过 `read_skill_reference` 工具的 `file` 参数按需读取；不需要一次加载全部。需要剧本以外的画布工作时，应交给相应的画布工作流，不能把文本草稿写入说成已生成分镜或媒体。

## 交付

按用户指定格式把**完整请求范围**写入草稿。长剧可按集或章节分批追加，每批核对人物状态和伏笔；不要写完计划就宣布全部剧本完成。完成前检查草稿里是否真的包含所承诺的集数、场景、人物设定或修改结果，并说明仍待补齐的内容。
